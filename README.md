# RIDUMU

index.html をブラウザで開くと遊べます。インストール、サーバー、外部API、ネット接続は不要です。

## 演奏の流れ

1. 「演奏開始」またはSpace。敵のBPMで4拍カウントイン。
2. **HI-HAT：Space / H / Hatパッド**で2小節演奏。リムショットの拍カウントを聴きながら、自分でHatの基準を作ります。
3. 4拍の切り替えカウント後、**A＝Kick / L＝Snare / タッチパッド**で2小節重ねます。録ったHatを録音時の補正で再生し、固定の自動Hatは鳴らしません。
4. Drumsで攻撃を準備、Bassでシールドを生成、Leadで支援を追加。Bass・Leadでは録ったHatと前のパートを伴奏にして演奏します。
5. Leadの後に全パートを再生。Drumsの発音に合わせて攻撃し、続いて敵の予告済みの攻撃を自動解決します。盾を先に消費し、残りだけHPへ入ります。防御の追加入力はありません。

1ターンは **Hat → Drums（攻撃）→ Bass（防御）→ Lead（支援）→ 戦闘再生 → 敵の攻撃**。次のDrumsで録音をリセットします。Hatは1ターンの最初だけ録音します。

### 戦闘ゾーンとパートの役割
32ステップ上のP＝POWERはDrumsの攻撃を強化、S＝SHIELDはBassに追加シールド、B＝BOOSTはLeadの支援を強化します。ゾーンは敵・ターンで移動し、3パートの構築中は固定です。補正前の入力位置を最寄りの16分スロットに近似して判定します。ゾーン以外でも通常の攻撃・盾・支援は成立し、同一マスの連打でゾーンボーナスは増えません。

Bassは強拍・長押しの実際の占有時間・2小節の反復・Kickと重なる位置から盾を作ります。長音の重複は二重計上しません。盾は上限90で残量を次のターンへ持ち越します。Leadは上昇フレーズで攻撃倍率、下降で敵攻撃の軽減、反復で命中、音程の広がりで属性効果、長音で盾効率、裏拍配置でブレイク性能を支援します。Lead自体は追加ダメージの音符として扱いません。

敵の攻撃は種類別のチャージ・叩きつけ／突進／電撃／毒／衝撃波と合成効果音で表現します。事前予告の威力を基準に、Leadの弱体化と土の軽減を適用し、盾→HPの順で解決します。盾とLead効果は戦闘終了・敵変更でリセットされます。

GridEffects.register(type, definition)で役割と表示を登録でき、GridEffects.inspectでノートと効果ゾーンの交差を取得できます。POISON/MUTE/DELAY/ECHO/BREAK/HEAL/FORCE QUANTIZEは将来用の型名を公開。毒の入力時処理は既存grid-hazards.jsで独立管理し、再生中の二重発動を防ぎます。

各フェーズのカウントインは最後の1拍から先取り入力できます。生演奏モードでは発音と再生に入力した時刻を使い、解析用の16分グリッドに入力を強制しません。長押しによるOSキーリピートは除外します。

## 演奏のクオンタイズ

入力エリアの「補正」で、録音前にモードを選べます。

- **生演奏**：従来どおり、入力した時刻で鳴ります。
- **ジャスト**：再生時に最寄りの16分音符の位置へ揃えます。
- **レイドバック**：16分へ揃え、高音側を35ms後ろに配置します。Hatと低音側はジャストです。
- **前ノリスネア**：再生時にSnareだけ16分へ揃えて、BPMに応じて24〜40ms前へ配置します（現在の敵BPM）。KickとHatは生タイミングのままです。
- **ドランク**：小節ごとに同じ不均等なズレを繰り返します。毎回のランダム化ではありません。
- **スウィング**：8分裏拍を遅らせ、長短のノリを作ります。

ライブ音と保存する演奏は、どのモードでも入力したタイミングのままです。補正は録音後の伴奏・攻撃・リプレイを作るときだけ適用します。ジャストでは早めの0.48秒も遅めの0.52秒も、最寄りの0.50秒へ揃えます。レイドバックなどのずらしは、そのグリッド位置へ加えます。

録音中のrawT / inputTは元の入力時刻を保持します。再生用コピーではrawTが補正後の発音位置になり、inputT / inputTimesに元の入力を残します。同じ音が同じ位置に集まった場合も、まとめるのは再生用コピーだけです。通常のリズム特徴と結果のシーケンサーは、再生する補正後の音を扱います。Hat基準のグルーヴ判定は元の録音（inputT / raw timestamp）を使います。補正を選んだだけで前ノリスネアなどのグルーヴ実績にはなりません。

モードは録音中には変更できません。途中のターンでモードを変更しても、すでに録ったHatや伴奏は録音時に選んだ補正を維持します。

## 敵のテンポとグルーヴ

| 敵 | BPM | 2小節の長さ |
| --- | --- | --- |
| 苔岩の番人 | 82 | 約5.85秒 |
| 宙を舞う翼獣 | 150 | 3.2秒 |
| 忘却の自律機 | 120 | 4秒 |
| 棘冠の喰らい花 | 100 | 4.8秒 |
| 薄明の残響 | 72 | 約6.67秒 |
| 晶殻の甲虫 | 138 | 約3.48秒 |

カウントイン・拍ランプ・録音時間・解析グリッド・再生が敵のBPMに追従します。速い敵ほど一律に強くする設計ではありません。敵ごとに異なるノリが有効になり、有効な相性は攻撃して発見します。

Hatの平均間隔・平均ズレ・前後の置き方・裏拍・均一性・スウィング・繰り返すズレ・小節単位の再現性・ランダムな不安定さを記録します。Kick/Snareは近いHatとの生時刻差も解析し、pocket / laidBack / pushed / snarePushed / swing / drunk / tight / unstable を連続値で保持します。Hatが少ないときはグルーヴを捏造せず、従来の音の特徴で攻撃します。

一定のSnareの前ノリ・遅れや、繰り返す非等間隔パターンは「不安定」と区別します。音種ごとの平均差を取り除いてから複雑な揺れを評価するため、単純なKick前／Snare後を自動でドランクにはしません。2小節内の反復から推定するMVPであり、プレイヤーの意図そのものを確定するものではありません。

## 継続して使える要素

- ドラム → ベース → シンセリードの3パート周期。Hatはセットの最初だけ録音し、同じHatと前の入力パートを伴奏として重ねられます。ドラムに戻ると全パートをリセット。次の敵も新しいHat・ドラムから開始します。
- 土・風・火・雷の4属性と既存リズム解析。ノリが威力・命中効率・安定度・属性・敵との相性にも影響します。Hatや過去の伴奏は直接の追加打撃に換算しません。
- 原タイミングの手動リプレイ。録音時のBPM・長さ・全パートを保持します。
- 命中時の弱点ラベル、最大3要因の説明、合計と一致するダメージ内訳、Hatを含む3段シーケンサーと原因ハイライト。
- 「SnareがHatより平均35ms後ろ → レイドバック」など、音楽的な言葉で結果を説明します。
- 発見した弱点・グルーヴ相性は敵の上部と「発見メモ」で確認できます。localStorage に保存し、保存できない環境ではプレイ中だけ保持します。
- 狭い画面は結果説明・リズム表示を切り替え、小さい横画面では内訳とヒントも分けます。

## ファイルと検証

- quantize.js：再生用コピーへのクオンタイズ・グルーヴプリセット。元の録音は変更しません。
- rhythm.js：既存特徴量・4属性・敵相性・ダメージと内訳・再生時刻。
- grid-effects.js / performance-combat.js：戦闘ゾーン、Bassの盾、Leadの支援、盾→HPの自動解決。
- game.js：2フェーズ進行、Web Audio合成音、記録・再生・戦闘・可視化。
- feedback.js / feedback-ui.js：説明・原因選択・弱点発見・保存。
- style.css / feedback.css / groove.css：画面構成。
- enemies.css：敵別のシルエット・パーツ・常時アニメーション・ヒット／弱点／回避／帯電／炎の短いリアクション。動きを減らすOS設定にも対応。

ベース・リードは A / L またはパッドの長押しで持続音になります。離すと減衰し、押した長さも伴奏・攻撃再生・リプレイで再現します。ドラムとHatは単発音のままです。再生補正は音の開始時刻に適用し、長押しの長さは保持します。

### ベース・リードの7音モード
演奏前に音数を「7音」に切り替えると、ベース・リードで C・D・E♭・F・G・A♭・B♭（Cナチュラルマイナー）を演奏できます。キーは順に A・S・D・F・G・H・J。画面の7パッドはタッチ・複数同時押し・長押しに対応します。ドラムは従来のA / L、HatはSpace / Hのままです。音高と音の長さは各パートの伴奏・攻撃再生・リプレイにも保持されます。戦闘解析では低い4音をKick側、高い3音をSnare側として扱い、従来のリズム評価を維持します。

4音モードは A・S・K・L で C・E♭・G・B♭ を演奏します。画面も4パッドに切り替わり、長押し・同時押し・再生補正・重ね再生に対応します。

### キーの音高変更
演奏前の「音高」からベース／リードと2音／4音／7音を選び、各キーの音名・オクターブ（C0〜B7）を自由に変更できます。「試聴」で確認し、「初期値に戻す」で選択中の楽器・音数の設定だけを戻せます。設定は自動保存されます。録音時の絶対音高を記録するため、後から設定を変更しても録音済みの伴奏・攻撃再生・リプレイの音程は変わりません。リズム評価での低音側／高音側の分類はキー位置に基づきます。

前ノリスネアはSnareとHatの平均差・差の一貫性・入力数から連続スコアを計算します。Kickの前ノリとは独立し、一定の先行をドランクとして加点しません。成立時は「SnareがHatより平均30ms前 → 前ノリスネア」のように説明し、原因のSnareをマークします。飛行敵との有効な相性は攻撃後に発見・保存されます。

### ドラム音源
Kick・Snare・HiHatはassets内のClark Audio WAVを使用します。演奏・伴奏・攻撃・リプレイで共通のWeb Audioバッファを使い、連打は重ねて鳴らします。リムショットのカウントとベース／リード／コードは従来の合成音です。
ファイルを直接開いても動くよう、元のWAVをassets/drum-samples.jsへ格納しています。WAVを差し替えたら `node scripts/build-drum-samples.cjs` で再生成してください。

### ブーンバップ・ベース
ベースはsine主体にtriangleとごく少量のsawtoothを重ね、オクターブ下の補助音を取り除きました。短いアタックと減衰、丸いローパス、軽いtanhサチュレーション、ベース専用の緩やかなコンプレッションを通します。短押しは短く太く、長押しは持続し、キーを離すと素早く減衰します。既存のマスターコンプレッサーは維持しています。
Kick音源の発音に合わせ、ベース専用バスだけをごく短く浅く下げて重なりを整えます。音高・長押し記録・再生補正・リードとコードの音色は従来どおりです。実装と単体テストはbass-audio.js / bass-audio.test.cjsにあります。

### 演奏履歴・MIDI保存
画面上部の「履歴」で、各パートの記録後と全パートの戦闘再生時の演奏を再生できます。重ねた全パート・敵BPM・音高・長押しの長さ・再生補正後のタイミングを複製して保存し、元の入力時刻もJSONに残します。以前保存したコード付き履歴の試聴にも対応します。次のドラムでパートをリセットしても、履歴は消えません。
直近50件をlocalStorageに自動保存します。保存できない環境や容量不足の場合も、このプレイ中は履歴に残り、JSONで手元へ保存できます。JSONの読込でRIDUMUに戻せます。履歴は演奏・攻撃・防御中には開けず、再生が戦闘結果やHPを書き換えることはありません。
「MIDI保存」はStandard MIDI File形式（テンポ・各楽器のトラック・音符・音長）を書き出します。ドラムはGMの10チャンネル、ベース／リード／コードは別チャンネルです。先取り入力の相対時刻も保持します。MIDIには音源そのものを含まないため、外部の再生ソフトでは音色が変わります。

### シーケンサー干渉：毒汚染
苔岩の番人（3マス・1入力3HP・4ターン）と棘冠の喰らい花（5マス・1入力4HP・5ターン）は毒汚染を使います。次の行動を敵の下に予告し、初回演奏後とリード後の実際の反撃時に汚染を追加します。行動停止・回避で反撃が消えた場合や、敵を倒した場合はその反撃による追加汚染も発生しません。
汚染は次の演奏ターンから有効になります。紫の帯が危険範囲、紫の32マス表示が中心とその周辺を示します。帯の中心から前後0.75スロットに、補正前のraw入力が入るとダメージを受けます。危険でも発音・記録は行われ、入力を禁止しません。同じ範囲の連打も1入力ごとにダメージです。ベース・リードの低音側／高音側入力も対象です。長押しの持続や、伴奏・攻撃再生・履歴再生では毒の追加判定は行いません。
残りターンはプレイヤーの各パート終了時に進み、Hatとドラムは同じターンとして扱います。発生した敵行動のターン中には寿命を減らしません。新しい汚染は既存の汚染と共存し、個別に期限を持ちます。同じ入力に複数の毒が重なった場合は、最も強い毒のダメージを1回受けます。勝利・敗北・敵変更・再挑戦時に全汚染をリセットします。毒で力尽きた場合は録音の時計を止め、以後の攻撃や反撃へ進みません。
`grid-hazards.js` はDOM・音・戦闘処理から独立した汎用システムです。`add`（発生ターン・寿命・対象入力・半径）、`advanceToTurn`、`onInput`、`reset` を提供します。`register(type, resolver)` で、該当するマスと入力文脈から効果記述子の配列を返す処理を追加できます。各汚染の `params` に将来の遅延量・反復数などを保持でき、ハンドラーには元の音高・音種・voiceなどの入力文脈も渡します。現段階で登録する実効果はpoisonのdamageだけです。mute / delay / forceQuantize / echo / shieldBreak は種別と拡張点のみ用意し、音や判定への効果は未実装です。描画は `grid-hazards.css` とゲームのCanvasで行います。


### 3パートのリズムシナジー
独立した `ensemble.js` が補正前のDrums/Bass/Leadを解析します。GROOVE LOCK（KickとBassの近接）、RESPONSE（アクセント後のLead）、INTERLOCK（空白の補完）、UNISON（限られた重要拍の共有）、CALL & RESPONSE（遅れて返す非等間隔モチーフ）の5種類です。音高はモチーフ照合に使いません。

最も強い2種類だけを適用し、2つ目は60%へ逓減します。音数ではなくユニークな配置と関係の割合を評価し、過密なトラックは減点。攻撃倍率ボーナスはブレイク分を含め最大20%、追加の盾は最大6です。Leadの支援倍率、命中、盾効率、属性効果、次の反撃への耐性にも種類別の補正を加えます。反撃への耐性はその演奏直後の攻撃だけに適用し、次のDrumsでシナジー状態を消去します。単独パートの基本効果は変えません。

結果の「シナジー」タブで最大2件の理由と実際のボーナスを表示します。3パートの小型シーケンサーの点線枠は成立箇所です。追加検証：`node --test ensemble.test.cjs`。


### 敵パラメータの強化
HP／攻撃力：苔岩260／88、翼獣240／96、自律機300／104、喰らい花280／96、残響270／100、晶殻340／116。BPM・弱点・毒の性能・プレイヤー側の計算は維持しています。


### ダメージの計算詳細
戦闘結果のダメージ直下にある「計算詳細」から開きます。Drumsの基礎威力、重さ・溜め・交互入力・ノリ、POWER／Lead／シナジーの段階別倍率、敵相性とグルーヴ相性、多段の配分、命中効率、演奏の安定度による固定倍率を確認できます。各打撃は演奏評価値だけで決まり、命中抽選や威力のランダム変動はありません。表のダメージ合計は結果と一致します。表示数値は丸めています。

今回の変更では攻撃バランスを一律に弱体化せず、倍率が重なって大きくなる経路を追えるようにしています。計算詳細はモーダル内だけでスクロールし、閉じると元の戦闘画面へ戻ります。


### 決定論的な戦闘ダメージ
Rhythm.resolveは乱数を使いません。各打撃は `power / hits^0.85 × affinity × 命中効率 × 安定度 × リズム精度` を四捨五入します。命中効率は敵との関係を反映したaccuracyを0〜1に制限した値、安定度は `1 − 0.3 × instability（0〜1）` です。効率0は0、それ以外は最低1ダメージ。無入力は0HIT・0ダメージです。現在は1回の攻撃内の各HITも同じ固定ダメージになります。
同じ演奏・同じ敵・同じ支援／シナジー／ゾーン等の状態なら完全に同じ結果になります。意図した後ノリ・ドランク等の評価方法は維持し、グルーヴ解析が算出した不安定さだけに固定ペナルティを適用します。


### 相性ダメージのメリハリ
属性・攻撃形態・敵とのグルーヴ相性を合成した倍率を1.65乗し、最終相性を0.4〜3倍に制限します。中立の1倍は維持。有効な相性1.5倍は約1.95倍へ、苦手な相性0.8倍は約0.69倍へ変化します。支援やシナジーの基本倍率、敵パラメータ、命中効率・安定度の算出は維持し、敵に合わせた攻撃の価値を強めています。計算詳細の「相性メリハリ補正」で変化分を確認できます。


### 演奏自体の規則性・巧さ
相性とは別に、Drumsの入力間隔の規則性と、8／16ステップ単位のフレーズ・ズレ方の反復を生時刻から評価します。規則的な刻み、または一貫した非等間隔モチーフは最大1.2倍、十分な入力数があり間隔もズレ方もばらばらな演奏は最低0.4倍になります。入力数が少ない場合は倍率を中立へ近づけ、3回以下の発音の重撃は減点しません。通常の32分・64分よりさらに細かい極端な連打で精度を稼ぐことも抑えています。

一定の後ノリ・スウィング・繰り返すドランクは単純な不規則として減点せず、パターンとズレの再現性から評価します。ライブ入力のraw timestamp／inputTimesを使い、再生補正による同一マスへの統合でも元の精度を保持します。計算詳細の「リズム精度」で固定倍率を確認でき、大きく減点された場合は短い原因説明も表示します。
