# RIDUMU

音声再生の回帰検証：`node scripts/attack-timbre-check.cjs`。ベース・リードの全プリセットのライブ／録音波形、演奏中の音色操作、実際のLead録音終了から攻撃への引き継ぎ、再生補正と音色参照時刻、攻撃時の伴奏バランス、マスターのピーク保護による他パートへの影響を確認します。マスターは −3 dB・ハードニーのピーク保護とし、従来の広いニーによる常時圧縮を避けます。ローグライトの音響報酬は引き続き有効です。

画面はシンプル表示で開始します。「メニュー → 画面をカスタマイズ」で、属性予測・進行一覧・発見メモ・敵の説明・結果の解説・背景波形を個別に切り替え、横画面の左右配置、結果とタイムラインの位置を変更できます。設定はブラウザに保存され、「シンプルに戻す」で初期化できます。機材一覧は「機材を見る」で展開します。小さい画面では縦にスクロールできます。表示設定の検証は `node scripts/layout-browser-check.cjs`（Playwrightを使用）。

## 敵に合わせたコード伴奏

コード進行と音色に加え、和音を弾く位置・長さ・強弱・休符・微小な前後差も敵ごとに変わります。プレイヤーが試せる有効なリズムを聴覚上の手掛かりにする伴奏です。和音だけでプレイヤーの入力や戦闘評価が変わるわけではありません。

| 敵 | 伴奏のリズム |
| --- | --- |
| 苔岩の番人 | 長めの和音と間、後続の和音を少し後ろへ |
| 宙を舞う翼獣 | 軽い一定の刻み、交互の強弱と少し前のアクセント |
| 忘却の自律機 | 表拍を空けた短い裏拍の和音 |
| 棘冠の喰らい花 | 前半の間、後半の加速と跳ね |
| 薄明の残響 | 毎回同じ前後のズレを持つドランクの揺れ |
| 晶殻の甲虫 | 同じ強弱の反復とポケットの前後差 |
| 炉心の舞踏獣 | 休符を挟む跳ねた呼び掛けと返答 |
| 脈動の浮遊核 | 2拍ずつの持続和音。実際のKickに反応して音量が沈み、戻る |
| 終奏の指揮者 | 軸を残した後半の変化、加速から最後の休符へ |

和声は従来どおり2拍ごとに進み、伴奏全体は演奏と同じ8拍でループします。新しい保存データは発音位置・ゲート長・強弱・時間差を伴奏スナップショットに含み、戦闘再生・履歴再生・JSON保存・MIDI出力でも保持します。リズム情報のない従来の伴奏データは、元の2拍ごとの持続和音で再生します。ミュート解除でも本来の休符を保ち、メニュー・カウントイン・敵の反撃中は既存どおり鳴りません。

## レイドバックの置き分け

Snare単独の遅れに加え、KickとSnareを後ろに置く形、小節頭のKickを保って後続Kickを遅らせる形も評価します。楽器全体の平均だけでなく、別小節の同じ位置での再現性を調べるため、頭のKickと2つ目のKickを違う位置に置いても精度は落ちません。KickとSnareの遅れが安定して連動する場合は小さな追加効果があります。再生補正の「レイドバック（Snare）」「レイドバック（Kickも後ろ）」で聴き比べられます。補正で元の演奏評価は上がりません。調査の出典・ゲーム上の解釈・数値設定は [MICROTIMING_RESEARCH.md](MICROTIMING_RESEARCH.md) に記録しています。

## 軸を保ったリズムの変化

完全反復に加え、Snareを一定に保ってKickを足す・抜く・移動する演奏（逆の役割も含む）を評価します。2小節の前後だけでなく、小節内の前後2拍も比較するため、「ドン・カッ／ドンドン・カッ」を毎小節繰り返すビートも認識します。共通する軸とKickの基本配置が残り、変化が小さいほど高く評価します。単に後半を大量の音で埋めたり、軸ごと別の配置にしたりしても同じボーナスは付きません。

新しく加えた音を反復の失敗として扱わず、軸と変化のタイミングが正確なら、完全反復と同等の演奏精度を得られます。意図的な前後のズレも許容し、ばらつくタイミングでは評価が下がります。軸と変化の評価は、翼獣・晶殻以外で敵別のリズムの形補正に最大0.18、指揮者では最大0.30加算します（既存の上限を適用）。翼獣・晶殻には一定の交互打ち・反復の得意分野を残しています。結果の説明とダメージ計算詳細で確認できます。

## Bass・Leadのリズム精度

Bassを既に後ろに置かれたKickからさらに少し後ろへ置く奏法も、位置ごとの間隔が安定していれば「BASS LAID-BACK」として攻撃と盾の連携になります。同期との重複加点はせず、同じ連携予算を使います。結果欄に「後ノリ」、内訳にKickからの実際の遅延と誤差を表示します。演奏者の証言・知覚研究とゲーム上の解釈は [MICROTIMING_RESEARCH.md](MICROTIMING_RESEARCH.md) のBassの項を参照してください。

Bassの盾と音程による攻撃・耐性支援、Leadの攻撃・防御・音程支援には、補正再生前の入力から計算したリズム精度が作用します。自身のタイミングの反復を35%、他パートとの相対的なズレ方の再現を65%として、十分な入力がある場合に効果を0.8〜1.2倍にします。関係の評価がまだできない場合は自身の評価を使い、反復の証拠自体が不足する場合は1倍です。既存の盾や効果の上限は適用されます。

Bassは既に演奏したHat・Drums、LeadはHat・Drums・Bassを参照します。基準となる16分の位置から各音の差を取り、別小節の同じ配置と比較します。一定の前後のズレ、スウィング、不均等な反復も評価対象で、必ずしも同時に鳴らす必要はありません。単発のズレから正解を作らず、同じ形の反復が4入力以上・全体の60%以上で確認できた場合に評価します。複雑な形を選んで評価対象を減らすと、その分だけ得点が下がります。表示は結果欄のBass・Leadの正確さと、「解析・内訳」の各パートとの関係・適用倍率で確認できます。

## ローグライトの機材と進路

音響機材10種類を追加し、全22種類から選べます。報酬3択には音響機材を少なくとも1つ、従来のリズム機材を少なくとも1つ含めます。音響機材は装備中に常時音を変え、下記の条件を満たす演奏で戦闘強化が一巡に1回発動します。同じ機材の強化は音の深さ・残響・フィードバックと戦闘効果の両方を高めます。

| 音響機材 | 対象・音の変化 | 戦闘強化（Lv.1 → Lv.2） |
| --- | --- | --- |
| 灼熱マスター | 全体・ディストーション | 4打以上で攻撃 +8% → +12% |
| 余白の大聖堂 | 全体・リバーブ | 4打以上・休符20%以上で盾 +4 → +7 |
| 双影のコーラス | Lead・コーラス | 2打以上・Lead3音以上で攻撃 +8% → +12% |
| 深海のコーラス | Bass・コーラス | 2打以上・Bass長音30%以上で盾 +4 → +7 |
| 銀翼フランジャー | Lead・フランジャー | 4打以上・展開またはシンコペーション25%以上で貫通強度 +8% → +12% |
| 磁場フランジャー | Bass・フランジャー | 4打以上・Kick同期2回以上かGROOVE LOCKで攻撃 +8% → +12% |
| 応答のダブディレイ | Lead・BPM同期の付点8分ディレイ | 4打以上・反復40%以上か掛け合いで攻撃 +8% → +12% |
| 裏路地オートワウ | Bass・半拍周期のフィルター | 4打以上・裏拍またはシンコペーション30%以上で貫通強度 +8% → +12% |
| 幻流フェイザー | 全体・位相のうねり | 6打以上・SwingまたはDrunk35%以上で攻撃 +8% → +12% |
| 瞬きのトレモロ | Lead・8分音符の音量変化 | 4打以上・Lead4音以上・休符10%以上で盾 +4 → +7 |

打数はDrums、音数は演奏解析に採用された音符を指します。所持数の制限はなく、獲得した機材をすべて使用します。重複は何度でもレベルアップし、戦闘効果はLv.1の値に「Lv.2との差 ×（レベル−1）」を加えます。音響効果も高レベルほど深くなりますが、音割れ・発振を避ける範囲へ滑らかに調整します。音声経路はBass・Lead専用のラックから全体のラックへ進み、波形表示もエフェクト後の音を表示します。通常モードへの切り替えでエフェクトと残響を解除します。録音履歴・JSONには音響機材を保存し、履歴再生は保存時の構成を使用します。MIDIは音符・テンポのみです。実装はrogue-audio.js、実音の検証はscripts/rogue-audio-browser-check.cjsです。

ローグライトは全8戦。最初に機材を3候補から1つ選び、勝利ごとに機材と進路を選びます。最後は「終奏の指揮者」で、それまでの7体は重複しません。機材・強化・課題は今回の周回中に有効で、再挑戦時にリセットします。

- **機材は22種・所持数制限なし。** Kickと間、一定の交互入力、反復、休符、DrumsとLeadの応答、KickとBassの同期、Leadの旋律、防御準備、スウィング、裏拍、展開、Bass長音を条件に発動します。同じ機材の獲得は何度でもレベルアップに変わります。新規機材と強化を重ね、入れ替えずに蓄積できます。通常報酬はLv.1、強敵報酬はLv.2相当を獲得し、所持済みならその分レベルが加算されます。
- **効果は演奏一巡ごとに1回。** Drums→Bass→Leadの完了後、戦闘再生前に適用します。機材による攻撃増加・追加盾・HP回復・貫通強度の合計制限を撤廃しました。貫通は「1−（1−Leadの貫通率）÷（1＋機材の貫通強度合計）」で算出し、積むほど100%無視に近づきます。盾容量は90＋所持する盾機材の現在値合計へ成長します。HPは100まで回復します。無音では戦闘強化は発動せず、属性・音符・入力時刻は変えません。音響機材は再生音に作用します。発動機材と実際の追加量を機材欄に表示し、計算詳細・演奏比較にも反映します。
- **進路では敵・BPM・HP・攻撃・装甲・有効な演奏・報酬を確認。** 通常戦と強敵戦の候補から選択します。戦数が進むたびに同じ敵のHPは基準値の10%分、攻撃は3.5%分ずつ増加します。強敵はさらにHP20%増・攻撃12%増で、勝利報酬は2レベル分です。最終戦の直前はボスへの1本道です。
- **第2・第5戦の後に休憩所。** HP35回復、または所持機材を1つ強化し、その後に戦う敵を選びます。利用の代償は次の勝利の機材報酬。休憩では戦闘数が進まず、同じ休憩所は1回だけ利用できます。
- **第3・第6戦の後にセッション戦。** 通常戦と同じ敵のHPが10%増える代わりに、反復か休符の演奏課題を選べます。戦闘中に1回でも達成してから勝利すると、通常報酬に加えて所持機材を1つ強化。何度強化した機材でも選べます。機材未所持の場合はHP15回復に変わります。
- **勝利でHP18回復。** 選択画面はEscや「あとで選ぶ」で閉じて再開できます。候補は維持し、報酬は二重に受け取れません。進路決定後は新しい敵を確認してから演奏を開始できます。

ルールは `roguelite.js`、機材欄・報酬・進路UIは `roguelite-ui.js` / `roguelite.css`。`node --test roguelite.test.cjs` で進行・報酬・発動条件・累積成長・演奏比較を検証します。Playwrightが利用できる環境では `node scripts/roguelite-smoke.cjs` で画面操作・実戦計算・スマホのスクロール・8戦目までの進行を検証できます（`RIDUMU_BROWSER` でChromiumの実行ファイル、`RIDUMU_SCREENSHOTS` で画像出力先を指定可能）。

## 演奏の流れ

1. 「演奏開始」またはSpace。敵のBPMで4拍カウントイン。
2. **HI-HAT：Space / H / Hatパッド**で2小節演奏。リムショットの拍カウントを聴きながら、自分でHatの基準を作ります。
3. 4拍の切り替えカウント後、**A＝Kick / L＝Snare / タッチパッド**で2小節重ねます。録ったHatを録音時の補正で再生し、固定の自動Hatは鳴らしません。
4. Drumsで攻撃を準備、Bassでシールドを生成、Leadで支援を追加。Bass・Leadでは録ったHatと前のパートを伴奏にして演奏します。
5. Leadの後に全パートを再生。Drumsの発音に合わせて攻撃し、続いて敵の予告済みの攻撃を自動解決します。盾を先に消費し、残りだけHPへ入ります。防御の追加入力はありません。

1ターンは **Hat → Drums（攻撃）→ Bass（防御）→ Lead（支援）→ 戦闘再生 → 敵の攻撃**。次のDrumsで録音をリセットします。Hatは1ターンの最初だけ録音します。

### パートの役割
シーケンサーのP／S／B（POWER／SHIELD／BOOST）ゾーンは廃止しました。配置によるゾーンボーナスはなく、演奏そのものから攻撃・盾・支援を計算します。紫の毒エリアは独立した敵の仕組みとして維持します。

Bassは強拍・長押しの実際の占有時間・2小節の反復・Kickと重なる位置から盾を作ります。長音の重複は二重計上しません。盾は上限90で残量を次のターンへ持ち越します。Leadは上昇フレーズで攻撃倍率、下降で敵攻撃の軽減、同音反復で命中、小さな音程移動で属性効果、中程度の移動で攻撃支援、大きな跳躍でシールド貫通と命中低下を選べます。長音の盾効率と裏拍配置の支援も維持します。Lead自体は追加ダメージの音符として扱いません。音程の式は末尾を参照してください。

敵の攻撃は種類別のチャージ・叩きつけ／突進／電撃／毒／衝撃波と合成効果音で表現します。事前予告の威力を基準に、Leadの弱体化と土の軽減を適用し、盾→HPの順で解決します。盾とLead効果は戦闘終了・敵変更でリセットされます。

16分スロットへの変換はパート間の同期判定に使用します。毒の入力時処理はgrid-hazards.jsで独立管理し、再生中の二重発動を防ぎます。

各フェーズのカウントインは最後の1拍から先取り入力できます。生演奏モードでは発音と再生に入力した時刻を使い、解析用の16分グリッドに入力を強制しません。長押しによるOSキーリピートは除外します。

## 演奏のクオンタイズ

入力エリアの「補正」で、録音前にモードを選べます。

- **生演奏**：従来どおり、入力した時刻で鳴ります。
- **ジャスト**：再生時に最寄りの16分音符の位置へ揃えます。
- **レイドバック**：16分へ揃え、高音側を35ms後ろに配置します。Hatと低音側はジャストです。
- **前ノリスネア**：再生時にSnareだけ16分へ揃えて、BPMに応じて24〜40ms前へ配置します（現在の敵BPM）。KickとHatは生タイミングのままです。
- **ドランク**：小節ごとに同じ不均等なズレを繰り返します。毎回のランダム化ではありません。
- **スウィング**：8分裏拍を遅らせ、長短のノリを作ります。

ライブ音と保存する演奏は、どのモードでも入力したタイミングのままです。補正は録音後の伴奏・攻撃・リプレイを作るときだけ適用します。ジャストでは早めの0.48秒も遅めの0.52秒も、最寄りの0.50秒へ揃えます。レイドバックなどのずらしは、そのグリッド位置へ加えます。

録音中のrawT / inputTは元の入力時刻を保持します。再生用コピーではrawTが補正後の発音位置になり、inputT / inputTimesに元の入力を残します。同じ音が同じ位置に集まった場合も、まとめるのは再生用コピーだけです。通常のリズム特徴と結果のシーケンサーは、再生する補正後の音を扱います。Hat基準のグルーヴ判定は元の録音（inputT / raw timestamp）を使います。補正を選んだだけで前ノリスネアなどのグルーヴ実績にはなりません。

モードは録音中には変更できません。途中のターンでモードを変更しても、すでに録ったHatや伴奏は録音時に選んだ補正を維持します。

## 敵のテンポとグルーヴ

| 敵 | BPM | 2小節の長さ |
| --- | --- | --- |
| 苔岩の番人 | 82 | 約5.85秒 |
| 宙を舞う翼獣 | 150 | 3.2秒 |
| 忘却の自律機 | 120 | 4秒 |
| 棘冠の喰らい花 | 100 | 4.8秒 |
| 薄明の残響 | 72 | 約6.67秒 |
| 晶殻の甲虫 | 138 | 約3.48秒 |

カウントイン・拍ランプ・録音時間・解析グリッド・再生が敵のBPMに追従します。速い敵ほど一律に強くする設計ではありません。敵ごとに異なるノリが有効になり、有効な相性は攻撃して発見します。

Hatの平均間隔・平均ズレ・前後の置き方・裏拍・均一性・スウィング・繰り返すズレ・小節単位の再現性・ランダムな不安定さを記録します。Kick/Snareは近いHatとの生時刻差も解析し、pocket / laidBack / pushed / snarePushed / swing / drunk / tight / unstable を連続値で保持します。Hatが少ないときはグルーヴを捏造せず、従来の音の特徴で攻撃します。

一定のSnareの前ノリ・遅れや、繰り返す非等間隔パターンは「不安定」と区別します。音種ごとの平均差を取り除いてから複雑な揺れを評価するため、単純なKick前／Snare後を自動でドランクにはしません。2小節内の反復から推定するMVPであり、プレイヤーの意図そのものを確定するものではありません。

## 継続して使える要素

- ドラム → ベース → シンセリードの3パート周期。Hatはセットの最初だけ録音し、同じHatと前の入力パートを伴奏として重ねられます。ドラムに戻ると全パートをリセット。次の敵も新しいHat・ドラムから開始します。
- 土・風・火・雷の4属性と既存リズム解析。ノリが威力・命中効率・安定度・属性・敵との相性にも影響します。Hatや過去の伴奏は直接の追加打撃に換算しません。
- 原タイミングの手動リプレイ。録音時のBPM・長さ・全パートを保持します。
- 命中時の弱点ラベル、最大3要因の説明、合計と一致するダメージ内訳、Hatを含む3段シーケンサーと原因ハイライト。
- 「SnareがHatより平均35ms後ろ → レイドバック」など、音楽的な言葉で結果を説明します。
- 発見した弱点・グルーヴ相性は敵の上部と「発見メモ」で確認できます。localStorage に保存し、保存できない環境ではプレイ中だけ保持します。
- 狭い画面は結果説明・リズム表示を切り替え、小さい横画面では内訳とヒントも分けます。

ベース・リードは A / L またはパッドの長押しで持続音になります。離すと減衰し、押した長さも伴奏・攻撃再生・リプレイで再現します。ドラムとHatは単発音のままです。再生補正は音の開始時刻に適用し、長押しの長さは保持します。

### ベース・リードの7音・9音モード
9音モードは7音に上のC・Dを追加します。キーは `A S D F G H J K L`、初期値はBassがC2〜D3、LeadがC4〜D5のCナチュラルマイナー9音です。スマートフォンでは5列×2段に配置し、演奏画面の高さを増やしません。「音高」で各パートの9キーを個別に変更・保存でき、録音・履歴・JSON・MIDIでも上の2音を保持します。9音というモード自体に戦闘倍率はなく、既存の音程解析を使用します。ドラムとHatの操作は従来どおりです。

演奏前に音数を「7音」に切り替えると、ベース・リードで C・D・E♭・F・G・A♭・B♭（Cナチュラルマイナー）を演奏できます。キーは順に A・S・D・F・G・H・J。画面の7パッドはタッチ・複数同時押し・長押しに対応します。ドラムは従来のA / L、HatはSpace / Hのままです。音高と音の長さは各パートの伴奏・攻撃再生・リプレイにも保持されます。戦闘解析では低い4音をKick側、高い3音をSnare側として扱い、従来のリズム評価を維持します。

4音モードは A・S・K・L で C・E♭・G・B♭ を演奏します。画面も4パッドに切り替わり、長押し・同時押し・再生補正・重ね再生に対応します。

### キーの音高変更
演奏前の「音高」からベース／リードと2音／4音／7音／9音を選び、各キーの音名・オクターブ（C0〜B7）を自由に変更できます。「試聴」で確認し、「初期値に戻す」で選択中の楽器・音数の設定だけを戻せます。設定は自動保存されます。録音時の絶対音高を記録するため、後から設定を変更しても録音済みの伴奏・攻撃再生・リプレイの音程は変わりません。リズム評価での低音側／高音側の分類はキー位置に基づきます。

前ノリスネアはSnareとHatの平均差・差の一貫性・入力数から連続スコアを計算します。Kickの前ノリとは独立し、一定の先行をドランクとして加点しません。成立時は「SnareがHatより平均30ms前 → 前ノリスネア」のように説明し、原因のSnareをマークします。飛行敵との有効な相性は攻撃後に発見・保存されます。

### ドラム音源
Kick・Snare・HiHatはassets内のClark Audio WAVを使用します。演奏・伴奏・攻撃・リプレイで共通のWeb Audioバッファを使い、連打は重ねて鳴らします。リムショットのカウントとベース／リード／コードは従来の合成音です。
設定の「音域と音色」でKick・Snare・Hi-hatの音色を選択・試聴できます。Kickは1990s / Originalの2種類で、選択はブラウザに保存され、演奏・伴奏・履歴再生に共通で適用します。

ファイルを直接開いても動くよう、元のWAVをassets/drum-samples.jsへ格納しています。音色の追加はWAVをassetsへ置き、scripts/build-drum-samples.cjsのfilesへ固有ID・type（kick / snare / hat）・name・fileを登録し、`node scripts/build-drum-samples.cjs` で再生成してください。選択肢は自動で増えます。

### ブーンバップ・ベース
ベースはsine主体にtriangleとごく少量のsawtoothを重ね、オクターブ下の補助音を取り除きました。短いアタックと減衰、丸いローパス、軽いtanhサチュレーション、ベース専用の緩やかなコンプレッションを通します。短押しは短く太く、長押しは持続し、キーを離すと素早く減衰します。既存のマスターコンプレッサーは維持しています。
Kick音源の発音に合わせ、ベース専用バスだけをごく短く浅く下げて重なりを整えます。音高・長押し記録・再生補正・リードとコードの音色は従来どおりです。実装と単体テストはbass-audio.js / bass-audio.test.cjsにあります。

### 演奏履歴・MIDI保存
画面上部の「履歴」で、各パートの記録後と全パートの戦闘再生時の演奏を再生できます。重ねた全パート・敵BPM・音高・長押しの長さ・再生補正後のタイミングを複製して保存し、元の入力時刻もJSONに残します。以前保存したコード付き履歴の試聴にも対応します。次のドラムでパートをリセットしても、履歴は消えません。
直近50件をlocalStorageに自動保存します。保存できない環境や容量不足の場合も、このプレイ中は履歴に残り、JSONで手元へ保存できます。JSONの読込でRIDUMUに戻せます。履歴は演奏・攻撃・防御中には開けず、再生が戦闘結果やHPを書き換えることはありません。
「MIDI保存」はStandard MIDI File形式（テンポ・各楽器のトラック・音符・音長）を書き出します。ドラムはGMの10チャンネル、ベース／リード／コードは別チャンネルです。先取り入力の相対時刻も保持します。MIDIには音源そのものを含まないため、外部の再生ソフトでは音色が変わります。

### シーケンサー干渉：毒汚染
苔岩の番人（3マス・1入力3HP・4ターン）と棘冠の喰らい花（5マス・1入力4HP・5ターン）は毒汚染を使います。次の行動を敵の下に予告し、初回演奏後とリード後の実際の反撃時に汚染を追加します。行動停止・回避で反撃が消えた場合や、敵を倒した場合はその反撃による追加汚染も発生しません。
汚染は次の演奏ターンから有効になります。紫の帯が危険範囲、紫の32マス表示が中心とその周辺を示します。帯の中心から前後0.75スロットに、補正前のraw入力が入るとダメージを受けます。危険でも発音・記録は行われ、入力を禁止しません。同じ範囲の連打も1入力ごとにダメージです。ベース・リードの低音側／高音側入力も対象です。長押しの持続や、伴奏・攻撃再生・履歴再生では毒の追加判定は行いません。
残りターンはプレイヤーの各パート終了時に進み、Hatとドラムは同じターンとして扱います。発生した敵行動のターン中には寿命を減らしません。新しい汚染は既存の汚染と共存し、個別に期限を持ちます。同じ入力に複数の毒が重なった場合は、最も強い毒のダメージを1回受けます。勝利・敗北・敵変更・再挑戦時に全汚染をリセットします。毒で力尽きた場合は録音の時計を止め、以後の攻撃や反撃へ進みません。
`grid-hazards.js` はDOM・音・戦闘処理から独立した汎用システムです。`add`（発生ターン・寿命・対象入力・半径）、`advanceToTurn`、`onInput`、`reset` を提供します。`register(type, resolver)` で、該当するマスと入力文脈から効果記述子の配列を返す処理を追加できます。各汚染の `params` に将来の遅延量・反復数などを保持でき、ハンドラーには元の音高・音種・voiceなどの入力文脈も渡します。現段階で登録する実効果はpoisonのdamageだけです。mute / delay / forceQuantize / echo / shieldBreak は種別と拡張点のみ用意し、音や判定への効果は未実装です。描画は `grid-hazards.css` とゲームのCanvasで行います。


### 3パートのリズムシナジー
独立した `ensemble.js` が補正前のDrums/Bass/Leadを解析します。GROOVE LOCK（KickとBassの近接）、RESPONSE（アクセント後のLead）、INTERLOCK（空白の補完）、UNISON（限られた重要拍の共有）、CALL & RESPONSE（遅れて返す非等間隔モチーフ）の5種類です。音高はモチーフ照合に使いません。

最も強い2種類だけを適用し、2つ目は60%へ逓減します。音数ではなくユニークな配置と関係の割合を評価し、過密なトラックは減点。攻撃倍率ボーナスはブレイク分を含め最大20%、追加の盾は最大6です。Leadの支援倍率、命中、盾効率、属性効果、次の反撃への耐性にも種類別の補正を加えます。反撃への耐性はその演奏直後の攻撃だけに適用し、次のDrumsでシナジー状態を消去します。単独パートの基本効果は変えません。

結果の「シナジー」タブで最大2件の理由と実際のボーナスを表示します。3パートの小型シーケンサーの点線枠は成立箇所です。追加検証：`node --test ensemble.test.cjs`。

HP／攻撃力：苔岩260／88、翼獣240／96、自律機300／104、喰らい花280／96、残響270／100、晶殻340／116。BPM・弱点・毒の性能・プレイヤー側の計算は維持しています。


### ダメージの計算詳細
戦闘結果のダメージ直下にある「計算詳細」から開きます。Drumsの基礎威力、重さ・溜め・交互入力・ノリ、Lead／シナジーの段階別倍率、敵相性とグルーヴ相性、多段の配分、命中効率、リズム精度による固定倍率を確認できます。各打撃は演奏評価値だけで決まり、命中抽選や威力のランダム変動はありません。表のダメージ合計は結果と一致します。表示数値は丸めています。

今回の変更では攻撃バランスを一律に弱体化せず、倍率が重なって大きくなる経路を追えるようにしています。計算詳細はモーダル内だけでスクロールし、閉じると元の戦闘画面へ戻ります。


### 決定論的な戦闘ダメージ
通常モードは全9体です。7体目「炉心の舞踏獣」（BPM108・HP380）は風が有効で、休符とKick／Snareの掛け合いを評価し、強打から始まります。8体目「脈動の浮遊核」（BPM78・HP390）は土・拍頭のKickと余白が有効です。持続コードだけを実際に発音したKickでサイドチェインし、強弱に応じて最大95%沈め、約0.85拍で戻します。小音量の伴奏Kickでも沈み込みを強く保ちます。Snare・Hatでは沈まず、Kickを打たなければ持続します。伴奏・戦闘・履歴再生でも同じ仕組みを使い、設定はJSONに保存します（MIDIは音符のみ）。9体目「終奏の指揮者」（BPM126・HP440）は火が有効で、モチーフの部分変化と緊張からの解放を評価し、強化→貫通→防御→強打→回復→溜めの順に行動します。専用の見た目・伴奏・発見メモに対応し、浮遊核はローグライトの抽選にも含まれます。

開発モード（`?debug=1` または `#debug`）では、設定 → DEV → 「任意の敵と戦う」で全9体から選べます。HP・録音・汚染・敵の強化をリセットして通常戦のREADYへ移動します。録音・カウントイン中は中断して移動し、攻撃・反撃再生中は完了後に切り替えられます。

全8体×6条件×4属性の比較は `node scripts/damage-balance-check.cjs damage-balance-eight-enemies.json`。通常時の最適候補は炉心が風138（雷97）、指揮者が火118（雷81）。有限候補・音色補正なしでの比較であり、通しプレイの勝率を保証するものではありません。

行動への干渉、構造解析、Bassの防御拍、Leadの配置による支援は [COMBAT_SYSTEM.md](COMBAT_SYSTEM.md) を参照してください。敵の予告に合う演奏で、装甲・回復・強化・貫通そのものを抑えられます。弱点属性の火力だけを唯一の正解にはしません。現行の比較は `node scripts/damage-balance-check.cjs damage-balance-tactics.json` で再計算できます。

Rhythm.resolveは乱数を使いません。各打撃は `power / hits^0.85 × affinity × 命中効率 × 演奏再現性` を四捨五入します。命中効率は敵との関係を反映したaccuracyを0〜1に制限した値です。効率0は0、それ以外は最低1ダメージ。無入力は0HIT・0ダメージです。現在は1回の攻撃内の各HITも同じ固定ダメージになります。
同じ演奏・同じ敵・同じ支援／シナジー／ゾーン等の状態なら完全に同じ結果になります。意図した後ノリ・ドランク等の評価方法は維持し、単純な不規則さそのものにペナルティは与えません。


### 相性ダメージのメリハリ
属性・攻撃形態・敵とのグルーヴ相性を合成した倍率を1.65乗し、0.4〜3倍に制限します。中立の1倍は維持。有効な相性1.5倍は約1.95倍へ、苦手な相性0.8倍は約0.69倍へ変化します。行動予告へのボーナスはこの後に線形で適用し、合計上限3倍を維持します。防御への裏拍補正は最大1.50倍、強化への変則リズム補正は最大1.45倍。雷は機械・残響に有効で、それ以外の4体への基礎属性相性は0.85倍です。計算詳細の「相性メリハリ補正」と各行動の行で変化分を確認できます。最適候補の比較結果・譜面・再計算方法は [DAMAGE_BALANCE.md](DAMAGE_BALANCE.md) に記載しています。


### 演奏自体の規則性・巧さ
相性とは別に、Drumsの入力間隔の規則性と、8／16ステップ単位のフレーズ・ズレ方の反復を生時刻から評価します。規則的な刻み、または一貫した非等間隔モチーフは最大1.6倍、十分な入力数があり間隔もズレ方もばらばらな演奏は最低0.4倍になります。入力数が少ない場合は倍率を中立へ近づけ、3回以下の発音の重撃は減点しません。通常の32分・64分よりさらに細かい極端な連打で精度を稼ぐことも抑えています。

一定の後ノリ・スウィング・繰り返すドランクは単純な不規則として減点せず、パターンとズレの再現性から評価します。ライブ入力のraw timestamp／inputTimesを使い、再生補正による同一マスへの統合でも元の精度を保持します。計算詳細の「演奏再現性」で固定倍率を確認でき、大きく減点された場合は短い原因説明も表示します。


### 開発用：クオンタイズ後の評価比較
`index.html?debug=1`（または `index.html#debug`）で開くと、ヘッダーにDEVボタンが出ます。演奏を記録した後にDEVを開き、録音時の補正または任意の補正プリセットを選んで比較します。通常の起動ではボタンと記録フックは無効です。

通常評価は本番と同じ「再生用の並び＋raw基準の精度・グルーヴ・シナジー・ゾーン評価」です。補正後評価は再生用コピーの発音時刻を元入力として扱い、統合されたノートも1ノートとして、精度・グルーヴ・シナジー・ゾーン・支援・新規シールド・ダメージを再計算します。元の録音・HP・実際の戦闘結果・弱点発見・履歴は変更しません。毒の入力時ダメージも再発動しません。比較は録音終了時点の敵・BPM・ゾーンのスナップショットを使用し、持ち越し盾を除く新規生成量を表示します。

`evaluation-debug.js` は副作用のない比較処理、`evaluation-debug-ui.js` は開発専用UIです。検証：`node --test evaluation-debug.test.cjs`。

DEVの「最大ダメージ譜面を自動入力」「最小ダメージ譜面を自動入力（無音）」は、DrumsのREADY時に利用できます。Hat・Drums・Bass・Leadを設定して3パートを自動演奏し、通常の戦闘計算まで進みます。最大は曲頭のKick、低音・長音で支えるBass、休符・応答・主音への着地を持つLeadから成る2小節の候補を使い、現在の敵と行動予告に対して探索した最高値で、理論上限の保証はありません（音色・エフェクトは探索に含みません）。レイドバック／ドランクが有効な敵には、そのグルーヴが生時刻で十分に成立し、結果の説明とも一致する候補から最高値を選びます。Hatは曲頭から一定の8分を保ち、Snareの遅延・反復する揺れを比較します。2小節目のKickを抜く応答形もBassが拍頭を支えます。Bass・Leadの音価と音程はフレーズごとに設計し、役割を分けて探索します。調整前後の記録は [音楽性監査](MAX_CHART_MUSIC_AUDIT.md) / [調整後の譜面](MAX_CHART_MUSIC_CURRENT.md) を参照。最小は無音で0ダメージです。開始ボタンまたはEscで途中停止できます。

規則性・反復の評価が0.65を超えた範囲に追加ボーナスを設け、評価が高いほど加速的に報酬が増えるよう調整しました。最大精度ボーナスは従来の1.2倍から1.6倍へ引き上げ、低評価域の減点と少数の重撃の扱いは維持しています。通常プレイでは引き続きraw時刻、開発比較の補正後評価ではクオンタイズ後の時刻を使います。


### 実音声の戦闘波形
`battle-waveform.js` は、既存のマスターコンプレッサーと出力の間に1個のAnalyserNodeを挿入します。`getFloatTimeDomainData()`で実音声を読み、敵の背後の専用Canvasへ横方向の波形を描きます。元の音声データ、入力・判定・ダメージ計算、コンプレッサー設定は変更しません。音がない時は人工的な波形を生成しません。

Drumsの瞬発的な強調、Bassの持続する太い線、Leadの細かな波形を基調に、シールドの外向きパルス、大ダメージ／敵攻撃／毒／シナジーの短い演出を加えます。属性色は攻撃時だけ表示。グルーヴの前後・スウィング・再現する揺れ・不安定さは描画の位置や薄い残像として重ね、実波形サンプルには書き戻しません。

波形の解析バッファは使い回し、描画は最大320点、DPRは最大1.5。小さい表示領域では30fpsへ抑え、ResizeObserverでサイズへ追従します。非表示タブでは描画を停止し、OSの動きを減らす設定では追加の残像・パルスを抑制します。`BattleWaveform.registerRenderer(name, draw)` と `setRenderer(name)` で将来の円形波形・スペクトラム描画へ差し替えられ、描画フレームにはAnalyserNodeも渡します。`dispose()`は解析・描画を解放し、音声は元の直接出力へ戻します。

検証：`node --test battle-waveform.test.cjs`。

## ゲーム内シンセ

OSC 1に加えて、独立した波形・Mix・±24半音・Fineを持つOSC 2を使えます。Sub・Detune・オクターブ倍音も重ねられます。正弦波LFOは音符ごとに開始し、Rate（0.1〜12Hz）、Vibrato（0〜70cent）、Filter Wobble（0〜2400cent）を独立して調整できます。Driveはソフトクリップの原音／飽和音ブレンドです。発振器→フィルター→Drive→音量ADSRの順で発音し、編集画面をOSC 1・OSC 2・Filter・AMP・LFO・Driveに整理しました。LFOとDriveは必要なときに開けます。従来の録音は新機能を無効にして読み込みます。

「音色と戦闘の関係」には現在BPMで短く刻む／長く伸ばす演奏例の補正目安を表示します。戦闘の音色補正が使う項目はAttack・Releaseで、ほかの音作りの項目は直接の戦闘倍率を持ちません。録音後の「解析・内訳」では、保存した音色と実演奏から計算したBass・Lead各パートの攻撃への寄与、盾の補正率、攻撃の合算倍率、盾生成の増減値を確認できます。盾の数値は盾容量を適用する前の生成量です。

設定 → シンセの「おすすめプリセット」から、Bass / Leadに各6種類の音色を選べます。選ぶとすぐ適用され、「試聴」で鳴らせます。BassはDeep Sub・Round Finger・Pocket Pluck・Warm Analog・Rubber・Soft Drift、LeadはClear Pluck・Velvet Keys・Warm Solo・Glass Bell・Detuned Saw・Hollow Squareです。説明文を目安に、短い刻み・長音・柔らかさ・明瞭さで選べます。

追加したSubは1オクターブ下の正弦波の量（0〜70%）、Detuneは少し音程をずらした同じ波形を重ねる厚み（0〜30 cent）です。重ねた分の出力を補正し、初期値は両方0。各プリセットはADSR・フィルターの減衰・倍音も調整済みで、全項目を編集できます。気に入った調整は「自分の音色」で名前を付けて保存できます。Sub・Detuneの変更も録音・履歴・JSONに保持し、従来の録音では追加レイヤーを無効にして再生します。

演奏エリアの「シンセ」からBASS / LEADを個別に編集できます。Sine / Triangle / Saw / Square、Cutoff（80〜16000 Hz）、Resonance、Attack / Decay / Sustain / Releaseに対応。「試聴」で鳴らしながら調整でき、音色はブラウザに自動保存します。ドラムは従来の埋め込みサンプルです。設定ダイアログだけが必要に応じてスクロールし、演奏画面ではエフェクトパッドと演奏開始ボタンを表示します。

エフェクトパッドはマウス移動、スマートフォンのタッチ、矢印キーで操作します。上下が音量、左右がフィルター。LOW PASSは設定したCutoffから暗くし、HIGH PASSは低域を削りながら明るくします。パッドからマウス／指が離れると、音量100%・フィルター操作0%へ戻ります。シンセのCutoff設定自体は変えません。ベース／リードでは、パッド内の小さな4本のゲージにも音色属性を表示します。

音色の個性を示す内部の配分値は、波形の倍音、実効Cutoff、Resonance、ADSRから正規化します。この配分に戦闘倍率はありません。音色でドラムの属性や敵の弱点は変わりません。

戦闘の音色補正は、実際に演奏した平均音価と最初の発音時点のAttack・Releaseの相性です。短音と速いAttackは攻撃を最大6%上げ、盾を最大3.5%下げます。長音とReleaseは盾を最大6%上げ、攻撃を最大3.5%下げます。攻撃にはBass・Leadを各1/2、Bass盾生成にはBassを全量、Leadの盾支援はBass元盾を基準に1/2反映します。無音は補正なし。命中率・弱体化への音色補正は0です。

各パートの録音に、開始音色と音色・パッドの変化を保存します。カウントインの先取り入力にも対応します。バッキング、攻撃再生、リプレイ、履歴再生は保存したパートごとの音色を使用し、現在の設定を変更しても録音の音は変わりません。波形切り替え・Cutoff・音量はWeb Audioのオーディオ時刻で予約し、長いReleaseまで再生します。JSON書き出し／読み込みも音色とオートメーションを保持します。MIDIは従来どおり音符とテンポのデータで、この独自シンセの音色は含みません。古いJSONも読み込めますが、音色情報がない旧録音には現在のシンセ音色を使います。

実装は `synth.js`（音色・属性・保存形式）、`synth-audio.js`（発音・ADSR・オートメーション・Kickダッキング）、`synth-ui.js` / `synth.css`（編集画面とゲージ）に分離しています。ゲーム側は既存の共通コンプレッサーと波形アナライザーを利用し、シンセとドラムのフィルター経路を分けてCutoffの二重適用を避けています。戦闘結果にはパートごとの属性と補正、ダメージ計算詳細には合成した音色倍率を表示します。

検証：`node --test *.test.cjs`。ブラウザ検証は開発用のPlaywrightがある環境で `node scripts/synth-browser-check.cjs` を実行します（必要なら `RIDUMU_PLAYWRIGHT_PATH` と `RIDUMU_CHROME` で場所を指定）。ゲーム本体は引き続き外部ライブラリ・サーバー・ネット接続不要です。


BASS / LEADはそれぞれ独立したモノフォニック音源です。新しい音を押すと同じパートの前の音とReleaseの余韻を打ち切り、後から押した音を優先します。新しい音を離しても、押したままの古い音へは戻りません。切り替え時は短いフェードでクリックを抑えます。BassとLeadは同時に鳴らせます。録音は前の音の長さを切り替え位置で確定し、既存の重なった録音も再生時に同じ規則で発音します。


リードの初期音色はシンセ導入前の音を再現しています。Triangleに1オクターブ上のSineを18%重ね、Cutoffを3600→1800 Hzへ0.12秒で減衰。音量は指数カーブでAttack 0.008秒、Decay 0.072秒、Sustain 65%、Release 0.12秒です。「以前のリードに戻す」で復元できます。シンセには倍音量、Filter Decay、Filter Sustain、Linear / Exponentialの音量カーブを追加し、変更も録音・JSON・属性計算へ反映します。旧版の変更していない初期設定は自動移行し、カスタム設定と既存の録音は旧パラメータを補完して読み込みます。
### 演奏中心のUI
戦闘と演奏を常時表示し、現在のパート・次の操作・拍・2小節の進行を大きく示します。「設定」から再生補正、音数・音高、シンセ、記録・発見へアクセスできます。結果はダメージ／シールド／属性を先に表示し、「解析・内訳を見る」で従来のリズム、アンサンブル、計算内訳と再生を利用できます。

「効果」は戦闘エリアに重ねて開くため、演奏パッドと開始ボタンの位置や大きさは変わりません。開閉状態をブラウザに保存し、閉じるとパッド効果を初期値に戻します。設定・解析画面は内部でスクロールし、通常の演奏画面は画面内に収まります。

表示の組み立ては `ui.css`、既存エンジンを監視する案内・ダイアログ操作は `ui.js` に分離しています。音声・判定・戦闘計算は従来の処理を使用します。検証：`node --test`、Playwright環境で `node scripts/ui-browser-check.cjs` と `node scripts/synth-browser-check.cjs`。
### 連続入力オプション
「設定」→「タイミング」→「連続入力」をONにすると、最初の開始操作だけでHAT → DRUMS → BASS → LEADへ2小節ずつ連続入力できます。開始時（戦闘後の再開を含む）は4拍のリムショットで入りを取り、手動HATの入力中は拍ごとのメトロノームを鳴らします。パート間はカウントインと開始操作を省略し、開始時刻を同じ音声クロック上で引き継ぎます。通常モードは従来どおりです。設定はブラウザに保存します。

リード後は従来の戦闘処理を行い、生存中は次のHATから自動継続します。停止ボタンまたはEscで入力を中断でき、入力中のパートは録り直しになります。完了済みのパートは保持します。戦闘中に停止した場合は戦闘完了後に止まり、撃破・敗北時も自動入力を終了します。

### ハイハット自動入力
「設定」→「タイミング」→「ハイハット自動入力」をONにすると、現在のBPMに合わせた2小節・16打の8分ハイハットを自動生成し、HAT入力を省略してDRUMSから始めます。通常入力／連続入力の両方で使え、最初の4拍のカウントインは維持します。生成したイベントは手動HATと同じ伴奏・グルーヴ解析・録音履歴・再生に使用します。新しい周期ごとに生成し直し、すでに録音済みのHATは上書きしません。設定はブラウザに保存され、演奏中の変更は無効です。
### パート切り替え時の先行入力
連続入力では、次のパート開始の最大150ms前（速いBPMでは半拍以内）から入力を受け付けます。HAT → DRUMS、DRUMS → BASS、BASS → LEADが対象です。この短い区間のパート用キー／パッドは次の音色・音高で即座に鳴り、次のトラックへ一度だけ記録されます。HAT用の入力は引き続きHATへ入り、LEAD末尾から戦闘への切り替えは先行入力の対象外です。

前のパートの末尾や長押しは切らず、先行入力した音の長押しも境界をまたいで持続します。表示上の開始位置は0に収め、生の負の入力時刻・音の長さ・シンセ設定は既存の録音／再生／グルーヴ解析へ引き継ぎます。通常のカウントイン中の早押し受付は従来どおりです。
### 敵ごとのコード伴奏
新しい演奏の履歴には、その時のコード進行・構成音・BPM・波形・フィルター・ADSR・音量を保存します。ダメージ判定、結果のリプレイ、履歴の再生は保存値を使うため、敵やプリセットが変わっても録音時の伴奏を再現します。JSONの保存・読込でも保持し、MIDIには独立した伴奏トラックとして音符とテンポを書き出します（独自シンセの音色はMIDIに含みません）。伴奏情報がない以前の履歴は「コード情報なし」と表示し、元のパートを再生します。

`enemy-music.js` に、和音用の独立したポリフォニックシンセと音声クロックに基づく伴奏を用意しています。各コードは2拍、4コードで2小節（8拍）のループです。各演奏トラックと同じ長さです。コード伴奏は録音入力中と、ダメージ判定時の演奏再生中に鳴ります。開始ボタンを押した後でも、カウントイン中はリムショットだけでコードは鳴りません。

| --- | --- | --- |
| 苔岩の番人 | Cm7 → Abmaj7 → Fm7 → Gm7 | 温かい三角波 |
| 宙を舞う翼獣 | Ebmaj7 → Bb(add9) → Cm7 → Abmaj7 | 軽い正弦波 |

### 音高・音程による戦術

`pitch-combat.js` は録音されたMIDI番号を用いる、乱数なし・パート別の評価です。BassとLeadの和声判定は行いません。補正前の入力時刻で16分枠に分け、各枠の最後の音だけを採用します（2小節で最大32音）。同時押しもモノフォニック音源と同じ後発優先です。長押しは1音と数え、リズム側では従来どおり占有時間を評価します。

隣接音の差は半音単位です。0＝同音、1～2＝小移動、3～6＝中移動、7以上＝跳躍。以下の「比率」は隣接する全音程に対する割合、信頼度 `c=min(1,音程数/3)` です。3音程（4音）で信頼度が飽和し、それ以上の連打に音数ボーナスはありません。上昇・下降にはさらに `方向係数=0.5+0.5×その方向への始終音差/全移動半音数` を掛けるため、往復だけで一方向の最大効果は得られません。

| Leadの演奏 | 音程由来の補正上限と計算 |
| --- | --- |
| 上昇 | 攻撃 +12% × 上昇比率 × 方向係数 × c |
| 下降 | 今回の反撃の威力 −16% × 下降比率 × 方向係数 × c |
| 同音反復 | 命中効率 +6ポイント × 同音比率 × c |
| 1～2半音 | 属性効果 +18% × 小移動比率 × c |
| 3～6半音 | 攻撃 +10% × 中移動比率 × c |
| 7半音以上 | 敵シールド貫通 +30% × 跳躍比率 × c、命中効率 −5ポイント × 同じ比率 × c |

上昇と中移動の攻撃支援は加算（Lead最大22%）。命中効率は確率ではなく固定のダメージ倍率で、上限99%。反復を混ぜると跳躍の命中低下を補えます。属性効果の増分は上限1を適用し、その実増分比率の25%を敵相性倍率に加算します（最大×1.045）。土では既存の反撃軽減にも効果量が反映されます。リズム・グルーヴ・音色・アンサンブルの既存補正とは別の段階で一度だけ適用し、以前の簡易的な上昇・下降・同音・音域の補正は置き換えています。

Bassは、入力時に選べた音高をソートした相対順位を各音に `register`（0＝最低、1＝最高）として保存します。低音度は `平均 max(0,0.5-register)×2`、高音度は `平均 max(0,register-0.5)×2`。オクターブ移動など絶対MIDI番号の変更で有利にならず、全キー同じ音高なら中立です。

| Bassの演奏 | 効果 |
| --- | --- |
| 低音側を多く使う | リズム由来の盾 ×（1＋最大16%×低音度） |
| 高音側を多く使う | 盾 −最大12%×高音度、Drumsへの攻撃支援 ＋最大10%×高音度 |
| 同音反復 | 盾 ＋最大8%×同音比率×c |
| 上下に方向転換 | 今回の反撃の威力 −最大12%×方向転換率×c |

盾の3つの音程補正は率を合算して丸め、音色補正と盾上限90を適用します。Bass入力結果では、その時点で実際に増減した盾を、音色・上限適用後の反実仮想差分で表示します。Lead後の盾効率・音色による追加盾は従来の段階で計算します。BassとLeadの音程攻撃支援は合わせて最大32%、全ての弱体化・土・音色・アンサンブル・音程耐性を合わせた敵攻撃軽減は最大55%です。方向転換率は同音を除いた移動方向が変わる回数／（移動数−1）。耐性は直後の反撃にだけ使い、新しい録音周期で置き換えます。

岩の番人20%、自律機25%、晶殻の甲虫30%の装甲シールド軽減を設定しています。その他は装甲なし。実ダメージへ掛ける装甲倍率は `1−装甲率×(1−貫通率)`。例：装甲30%・貫通30%なら、軽減は21%になり、倍率は0.70から0.79になります。装甲のない敵には貫通の利点がなく、跳躍の命中コストは残るため使い分けが必要です。

2音は同音反復や安定した往復だけでも命中・盾・耐性を得られます。4音は小中移動と反復を組み合わせやすく、7音は跳躍も使いやすい選択肢です。モード名やキー数そのものを計算に渡していないため、同じMIDI列ならどのモードでも効果は同じです。キーのカスタマイズでも同じ原則です。

`pitch-ui.js` は既存シーケンサー内をBass／Lead別の簡易ピアノロールにし、音高を上下、長押しを横幅、音のつながりを線で表示します。↑／↓／＝／↯と色を併用し、演奏中の傾向を表示。結果には主要効果、解析の「音程の効果と旋律を見る」には両パートの図と適用値を表示します。最も強い効果は自動で、項目を選ぶとその効果は個別に音符・区間をハイライトします。補正上限・盾上限を適用した数値を使い、貫通と命中低下は一緒に表示します。メイン画面の高さは増やさず、詳細の開閉状態を保存。波形には上昇線・弱体波・鋭い貫通線・厚い盾・高音変換の輪郭を短く表示し、動きを減らす設定では省略します。

MIDI・相対順位・長さは演奏履歴とJSONで保持され、敵変更・音高設定変更後も再生の音高は変わりません。古いデータは従来のpitch／音種からMIDIを補い、順位のないBassは録音内の音高分布を使います。同音しかない旧Bassは中立音域として扱います。履歴再生ではHPや戦闘状態を変更しません。

検証：`node --test`、`node scripts/pitch-browser-check.cjs`（実戦のHP・盾消費／貫通／上限適用値／実キー記録／図のハイライト／8画面サイズ／履歴・保存復元）。既存の `synth-browser-check.cjs` と `ui-browser-check.cjs` でも演奏操作・音声・連続入力・タッチを確認します。

### ドラムのリアルタイム属性

シーケンサー上の「土・風・火・雷」は、ドラム入力の次の描画フレームで更新します。「予測」は途中の2小節解析、「確定」はドラム録音完了時のグルーヴ補正込みの判定です。Bass／Lead中もドラムの確定値を保持し、新しい録音・敵変更・再挑戦でリセットします。無入力は待機／無音、1〜2音では「予測?」とし優勢属性を強調しません。

`element-meter.js` は戦闘と同じ `Quantize.render → Rhythm.analyze → Groove.enrich`（Grooveは生のDrums／Hatから解析）を呼ぶ表示専用モジュールです。独自の属性計算や戦闘補正は追加しません。バーはスコア合計に対する表示割合で、上位2属性の差が首位スコアの8%以内なら「≈」と破線で競り合いを示します。この閾値は表示専用です。順位交代の短い動きはOSの「動きを減らす」と演出OFFに従います。

属性を選ぶと演奏ヒント、「?」で元スコアを確認できます。演奏中は短い表示のみ、待機中は説明を折りたためるダイアログを開きます。キック中心→土、交互＋スネア→風、後半の密度増加→火、裏拍→雷が目安ですが、実際の複合判定とグルーヴで変わります。音声・入力イベント内では解析せず、入力変更時だけ描画側で更新します。

検証：`node --test element-meter.test.cjs`、`node scripts/element-meter-browser-check.cjs`。各再生補正・録音途中のスコア一致、無音・少数入力・先行入力、実際の録音完了と確定値の保持／リセット、ヒントと9画面サイズを確認します。

### 演奏の因果関係・前回との比較

`performance-review.js` は既存のRhythm／Groove／PerformanceCombat／Ensemble／PitchCombat／Synthを使う読み取り専用の評価層です。戦闘式・敵の威力・HP・装甲率は変更しません。元の録音・音色スナップショットから、Drumsの攻撃、BassとLeadの盾、反撃までを再構成します。実戦の予定ダメージ・盾量と一致した場合だけ、その結果を使って追加の確定演出・要因表示・比較を行います。

演奏中は既存の部分解析で成立したものだけを、シーケンサー内に650ms表示します。「途中」と明記し、未入力の後半や他パートの未来の音は評価に含めません。Kick＋Bassの同期、Drums→Leadの応答、上昇・下降・跳躍・反復、低音の防壁／高音の攻撃支援を文字と形で区別します。グルーヴと再現性も既存解析の信頼度・成立度を使い、▰／▰▰／▰▰▰で段階を表します。解析は発音後の描画フレームにまとめ、発音や入力を待たせません。

全パート終了後は、補正を1つずつ無効にした反実仮想を再計算します。対象はDrumsの攻撃、Bassの盾、Leadの基本支援、属性・敵の形態相性、リズム再現性、グルーヴ、アンサンブル、音程、音色。敵の残HPで切り捨てた実ダメージ・盾上限・実際に防げたHPを比較し、利益のある要因を最大3つだけ表示します。撃破で捨てられる未使用の盾は利益に数えません。同期／応答の確定演出には、アンサンブル全体だけでなく、その選択された効果を単独で外した差分も使います。2番目の効果の60%係数は維持し、無効にした効果の代わりに3番目を採用することはありません。複数補正は相互作用するため、これらの差分は加算できません。

戦闘中は実際にダメージが入る打撃で短い主因を表示し、確定した同期・応答をその音符の再生位置で示します。盾は実際の増加がある場合だけ演出し、上限で増えない場合は成功演出を出しません。上昇線、弱体波、貫通線、反復の平行線、厚い盾、高音の変換線も実益を参照します。音色・属性・グルーヴ・再現性が攻撃に寄与した時も短く表示します。

音響は `feedback-audio.js` が既存シンセノートの専用表情段へ予約します。同期したBassは180Hzの低域を最大1dB、同期／応答の音量は最大6%だけ短く持ち上げ、120msで元へ戻します。新しい音符・人工効果音・オシレーターは追加しません。シンセ設定、録音データ、音色の戦闘属性には書き込まず、元の音を土台とする演出です。「設定 → 音域と音色」のチェックで追加の音響・視覚エフェクトを停止でき、OFFは表情段を完全に平坦へ戻します。設定を保存し、動きを減らす設定にも従います。既存の基本的な戦闘演出や解析情報は引き続き利用できます。

「解析・内訳 → 同じ敵への前回演奏との比較」では、この起動中の同じ敵に対する直前の戦闘と比較します。両録音を今回の敵性能・HP100・持ち越し盾0で再評価し、敵が生存して反撃する条件を共通にします。演奏のダメージ性能、生成盾、反撃のHPダメージ、属性相性、グルーヴ、アンサンブル、音程補正を比較。音数・間・長押し・同期・旋律などの変化を文章で説明し、その下に実戦の敵残HP・開始HP・持ち越し盾・撃破による反撃省略を別表示します。入力中の毒による減少は開始HPに含み、反撃ダメージと混同しません。前回データは敵別に最大6件をメモリ内で保持し、ページ再読込でリセットします。

次の工夫は現在の敵・未成立の効果・装甲・被ダメージ・上限から1つ選びます。直近3件のヒントを避けて、同じ提案が続かないようにします。無入力時はまず攻撃の土台を案内します。過去の履歴、結果リプレイ、MIDI／JSONには変更を加えず、再生で比較履歴やHPを更新しません。比較結果や演出のために戦闘結果へ乱数を導入しません。

検証：`node --test` と `node scripts/experience-browser-check.cjs`。2回の実戦と再構成の一致、同条件比較、条件差・上限・オーバーキル・未使用盾、ヒントの変化、途中評価の同期、OFFの実音声一致、8画面サイズ、履歴再生での非変更を確認します。
