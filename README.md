# RIDUMU

## 公開URLとブランチ運用

- 安定版（`main`）：https://kurono966.github.io/RIDUMU/
- 開発版（`experiment/chatgpt`）：https://kurono966.github.io/RIDUMU/dev/

通常の開発は `git switch experiment/chatgpt` → 編集・テスト → `git push origin experiment/chatgpt` で進め、開発版URLで動作を確認します。安定版へ反映するときは、GitHubで **base: main / compare: experiment/chatgpt** のPull Requestを作成し、確認後にマージします。`main` へのマージでも自動公開されます。既存の `develop` ブランチは削除せず保持しますが、公開元・自動公開のトリガーには使いません。

`.github/workflows/pages.yml` が `main` / `experiment/chatgpt` のプッシュ時に両ブランチの最新版を取得し、`main` のゲームをルート、`experiment/chatgpt` のゲームを `dev/` に配置した単一のPages成果物を公開します。全体を共通のconcurrencyグループで直列実行し、進行中のデプロイはキャンセルしません。待機後に最新の両ブランチを取得するため、一方の更新で他方を古い成果物に戻すことを防ぎます。GitHubが待機中の古い実行を新しい実行に置き換える場合もありますが、後続の実行は必ず両方の最新版を含みます。

両ブランチのテストと、HTML・CSS・JavaScriptの参照先検証に成功した場合だけ公開します。ゲーム本体の内容は書き換えず、公開対象はルートの静的ファイルと `assets/` に限定します。`.git`・テスト・ワークフロー・ビルドスクリプトは配信しません。`dev/` は生成時の開発版配置先として予約します。公開された `_deployment.json` で両ブランチの配信コミットを確認できます。ビルド処理自体は `main` の `scripts/build-pages.cjs` を使うため、公開処理の変更も両ブランチで同期してください。

初回設定・復旧時はリポジトリの **Settings → Pages → Build and deployment → Source: GitHub Actions** を選びます。**Settings → Environments → github-pages → Deployment branches and tags** で `main` と `experiment/chatgpt` を許可してください。Actionsは有効化し、公式 `actions/*` を許可します。公開ジョブにはワークフロー内で `contents: read` / `pages: write` / `id-token: write` を指定済みで、PATやリポジトリ全体の書き込み権限は不要です。手動で再公開するときは **Actions → Deploy RIDUMU stable and experiment/chatgptment → Run workflow** で `main` または `experiment/chatgpt` を指定します。片方のブランチがない場合は公開を失敗させ、前の公開サイトを維持します。

両URLは同一オリジンのため、既存仕様の `localStorage`（設定・履歴等）は共有されます。コードの配信はブランチ別に分離しています。ローカル検証は `node --test *.test.cjs`。独立した2つのチェックアウトを用意すれば `node scripts/build-pages.cjs <mainのフォルダー> <experiment/chatgptのフォルダー> <新しい出力フォルダー>` でも同じ成果物を作れます。

index.html をブラウザで開くと遊べます。インストール、サーバー、外部API、ネット接続は不要です。

## 演奏の流れ

1. 「演奏開始」またはSpace。敵のBPMで4拍カウントイン。
2. **HI-HAT：Space / H / Hatパッド**で2小節演奏。リムショットの拍カウントを聴きながら、自分でHatの基準を作ります。
3. 4拍の切り替えカウント後、**A＝Kick / L＝Snare / タッチパッド**で2小節重ねます。録ったHatを録音時の補正で再生し、固定の自動Hatは鳴らしません。
4. Drumsで攻撃を準備、Bassでシールドを生成、Leadで支援を追加。Bass・Leadでは録ったHatと前のパートを伴奏にして演奏します。
5. Leadの後に全パートを再生。Drumsの発音に合わせて攻撃し、続いて敵の予告済みの攻撃を自動解決します。盾を先に消費し、残りだけHPへ入ります。防御の追加入力はありません。

1ターンは **Hat → Drums（攻撃）→ Bass（防御）→ Lead（支援）→ 戦闘再生 → 敵の攻撃**。次のDrumsで録音をリセットします。Hatは1ターンの最初だけ録音します。

### 戦闘ゾーンとパートの役割
32ステップ上のP＝POWERはDrumsの攻撃を強化、S＝SHIELDはBassに追加シールド、B＝BOOSTはLeadの支援を強化します。ゾーンは敵・ターンで移動し、3パートの構築中は固定です。補正前の入力位置を最寄りの16分スロットに近似して判定します。ゾーン以外でも通常の攻撃・盾・支援は成立し、同一マスの連打でゾーンボーナスは増えません。

Bassは強拍・長押しの実際の占有時間・2小節の反復・Kickと重なる位置から盾を作ります。長音の重複は二重計上しません。盾は上限90で残量を次のターンへ持ち越します。Leadは上昇フレーズで攻撃倍率、下降で敵攻撃の軽減、反復で命中、音程の広がりで属性効果、長音で盾効率、裏拍配置でブレイク性能を支援します。Lead自体は追加ダメージの音符として扱いません。

敵の攻撃は種類別のチャージ・叩きつけ／突進／電撃／毒／衝撃波と合成効果音で表現します。事前予告の威力を基準に、Leadの弱体化と土の軽減を適用し、盾→HPの順で解決します。盾とLead効果は戦闘終了・敵変更でリセットされます。

GridEffects.register(type, definition)で役割と表示を登録でき、GridEffects.inspectでノートと効果ゾーンの交差を取得できます。POISON/MUTE/DELAY/ECHO/BREAK/HEAL/FORCE QUANTIZEは将来用の型名を公開。毒の入力時処理は既存grid-hazards.jsで独立管理し、再生中の二重発動を防ぎます。

各フェーズのカウントインは最後の1拍から先取り入力できます。生演奏モードでは発音と再生に入力した時刻を使い、解析用の16分グリッドに入力を強制しません。長押しによるOSキーリピートは除外します。

## 演奏のクオンタイズ

入力エリアの「補正」で、録音前にモードを選べます。

- **生演奏**：従来どおり、入力した時刻で鳴ります。
- **ジャスト**：再生時に最寄りの16分音符の位置へ揃えます。
- **レイドバック**：16分へ揃え、高音側を35ms後ろに配置します。Hatと低音側はジャストです。
- **前ノリスネア**：再生時にSnareだけ16分へ揃えて、BPMに応じて24〜40ms前へ配置します（現在の敵BPM）。KickとHatは生タイミングのままです。
- **ドランク**：小節ごとに同じ不均等なズレを繰り返します。毎回のランダム化ではありません。
- **スウィング**：8分裏拍を遅らせ、長短のノリを作ります。

ライブ音と保存する演奏は、どのモードでも入力したタイミングのままです。補正は録音後の伴奏・攻撃・リプレイを作るときだけ適用します。ジャストでは早めの0.48秒も遅めの0.52秒も、最寄りの0.50秒へ揃えます。レイドバックなどのずらしは、そのグリッド位置へ加えます。

録音中のrawT / inputTは元の入力時刻を保持します。再生用コピーではrawTが補正後の発音位置になり、inputT / inputTimesに元の入力を残します。同じ音が同じ位置に集まった場合も、まとめるのは再生用コピーだけです。通常のリズム特徴と結果のシーケンサーは、再生する補正後の音を扱います。Hat基準のグルーヴ判定は元の録音（inputT / raw timestamp）を使います。補正を選んだだけで前ノリスネアなどのグルーヴ実績にはなりません。

モードは録音中には変更できません。途中のターンでモードを変更しても、すでに録ったHatや伴奏は録音時に選んだ補正を維持します。

## 敵のテンポとグルーヴ

| 敵 | BPM | 2小節の長さ |
| --- | --- | --- |
| 苔岩の番人 | 82 | 約5.85秒 |
| 宙を舞う翼獣 | 150 | 3.2秒 |
| 忘却の自律機 | 120 | 4秒 |
| 棘冠の喰らい花 | 100 | 4.8秒 |
| 薄明の残響 | 72 | 約6.67秒 |
| 晶殻の甲虫 | 138 | 約3.48秒 |

カウントイン・拍ランプ・録音時間・解析グリッド・再生が敵のBPMに追従します。速い敵ほど一律に強くする設計ではありません。敵ごとに異なるノリが有効になり、有効な相性は攻撃して発見します。

Hatの平均間隔・平均ズレ・前後の置き方・裏拍・均一性・スウィング・繰り返すズレ・小節単位の再現性・ランダムな不安定さを記録します。Kick/Snareは近いHatとの生時刻差も解析し、pocket / laidBack / pushed / snarePushed / swing / drunk / tight / unstable を連続値で保持します。Hatが少ないときはグルーヴを捏造せず、従来の音の特徴で攻撃します。

一定のSnareの前ノリ・遅れや、繰り返す非等間隔パターンは「不安定」と区別します。音種ごとの平均差を取り除いてから複雑な揺れを評価するため、単純なKick前／Snare後を自動でドランクにはしません。2小節内の反復から推定するMVPであり、プレイヤーの意図そのものを確定するものではありません。

## 継続して使える要素

- ドラム → ベース → シンセリードの3パート周期。Hatはセットの最初だけ録音し、同じHatと前の入力パートを伴奏として重ねられます。ドラムに戻ると全パートをリセット。次の敵も新しいHat・ドラムから開始します。
- 土・風・火・雷の4属性と既存リズム解析。ノリが威力・命中効率・安定度・属性・敵との相性にも影響します。Hatや過去の伴奏は直接の追加打撃に換算しません。
- 原タイミングの手動リプレイ。録音時のBPM・長さ・全パートを保持します。
- 命中時の弱点ラベル、最大3要因の説明、合計と一致するダメージ内訳、Hatを含む3段シーケンサーと原因ハイライト。
- 「SnareがHatより平均35ms後ろ → レイドバック」など、音楽的な言葉で結果を説明します。
- 発見した弱点・グルーヴ相性は敵の上部と「発見メモ」で確認できます。localStorage に保存し、保存できない環境ではプレイ中だけ保持します。
- 狭い画面は結果説明・リズム表示を切り替え、小さい横画面では内訳とヒントも分けます。

ベース・リードは A / L またはパッドの長押しで持続音になります。離すと減衰し、押した長さも伴奏・攻撃再生・リプレイで再現します。ドラムとHatは単発音のままです。再生補正は音の開始時刻に適用し、長押しの長さは保持します。

### ベース・リードの7音モード
演奏前に音数を「7音」に切り替えると、ベース・リードで C・D・E♭・F・G・A♭・B♭（Cナチュラルマイナー）を演奏できます。キーは順に A・S・D・F・G・H・J。画面の7パッドはタッチ・複数同時押し・長押しに対応します。ドラムは従来のA / L、HatはSpace / Hのままです。音高と音の長さは各パートの伴奏・攻撃再生・リプレイにも保持されます。戦闘解析では低い4音をKick側、高い3音をSnare側として扱い、従来のリズム評価を維持します。

4音モードは A・S・K・L で C・E♭・G・B♭ を演奏します。画面も4パッドに切り替わり、長押し・同時押し・再生補正・重ね再生に対応します。

### キーの音高変更
演奏前の「音高」からベース／リードと2音／4音／7音を選び、各キーの音名・オクターブ（C0〜B7）を自由に変更できます。「試聴」で確認し、「初期値に戻す」で選択中の楽器・音数の設定だけを戻せます。設定は自動保存されます。録音時の絶対音高を記録するため、後から設定を変更しても録音済みの伴奏・攻撃再生・リプレイの音程は変わりません。リズム評価での低音側／高音側の分類はキー位置に基づきます。

前ノリスネアはSnareとHatの平均差・差の一貫性・入力数から連続スコアを計算します。Kickの前ノリとは独立し、一定の先行をドランクとして加点しません。成立時は「SnareがHatより平均30ms前 → 前ノリスネア」のように説明し、原因のSnareをマークします。飛行敵との有効な相性は攻撃後に発見・保存されます。

### ドラム音源
Kick・Snare・HiHatはassets内のClark Audio WAVを使用します。演奏・伴奏・攻撃・リプレイで共通のWeb Audioバッファを使い、連打は重ねて鳴らします。リムショットのカウントとベース／リード／コードは従来の合成音です。
ファイルを直接開いても動くよう、元のWAVをassets/drum-samples.jsへ格納しています。WAVを差し替えたら `node scripts/build-drum-samples.cjs` で再生成してください。

### ブーンバップ・ベース
ベースはsine主体にtriangleとごく少量のsawtoothを重ね、オクターブ下の補助音を取り除きました。短いアタックと減衰、丸いローパス、軽いtanhサチュレーション、ベース専用の緩やかなコンプレッションを通します。短押しは短く太く、長押しは持続し、キーを離すと素早く減衰します。既存のマスターコンプレッサーは維持しています。
Kick音源の発音に合わせ、ベース専用バスだけをごく短く浅く下げて重なりを整えます。音高・長押し記録・再生補正・リードとコードの音色は従来どおりです。実装と単体テストはbass-audio.js / bass-audio.test.cjsにあります。

### 演奏履歴・MIDI保存
画面上部の「履歴」で、各パートの記録後と全パートの戦闘再生時の演奏を再生できます。重ねた全パート・敵BPM・音高・長押しの長さ・再生補正後のタイミングを複製して保存し、元の入力時刻もJSONに残します。以前保存したコード付き履歴の試聴にも対応します。次のドラムでパートをリセットしても、履歴は消えません。
直近50件をlocalStorageに自動保存します。保存できない環境や容量不足の場合も、このプレイ中は履歴に残り、JSONで手元へ保存できます。JSONの読込でRIDUMUに戻せます。履歴は演奏・攻撃・防御中には開けず、再生が戦闘結果やHPを書き換えることはありません。
「MIDI保存」はStandard MIDI File形式（テンポ・各楽器のトラック・音符・音長）を書き出します。ドラムはGMの10チャンネル、ベース／リード／コードは別チャンネルです。先取り入力の相対時刻も保持します。MIDIには音源そのものを含まないため、外部の再生ソフトでは音色が変わります。

### シーケンサー干渉：毒汚染
苔岩の番人（3マス・1入力3HP・4ターン）と棘冠の喰らい花（5マス・1入力4HP・5ターン）は毒汚染を使います。次の行動を敵の下に予告し、初回演奏後とリード後の実際の反撃時に汚染を追加します。行動停止・回避で反撃が消えた場合や、敵を倒した場合はその反撃による追加汚染も発生しません。
汚染は次の演奏ターンから有効になります。紫の帯が危険範囲、紫の32マス表示が中心とその周辺を示します。帯の中心から前後0.75スロットに、補正前のraw入力が入るとダメージを受けます。危険でも発音・記録は行われ、入力を禁止しません。同じ範囲の連打も1入力ごとにダメージです。ベース・リードの低音側／高音側入力も対象です。長押しの持続や、伴奏・攻撃再生・履歴再生では毒の追加判定は行いません。
残りターンはプレイヤーの各パート終了時に進み、Hatとドラムは同じターンとして扱います。発生した敵行動のターン中には寿命を減らしません。新しい汚染は既存の汚染と共存し、個別に期限を持ちます。同じ入力に複数の毒が重なった場合は、最も強い毒のダメージを1回受けます。勝利・敗北・敵変更・再挑戦時に全汚染をリセットします。毒で力尽きた場合は録音の時計を止め、以後の攻撃や反撃へ進みません。
`grid-hazards.js` はDOM・音・戦闘処理から独立した汎用システムです。`add`（発生ターン・寿命・対象入力・半径）、`advanceToTurn`、`onInput`、`reset` を提供します。`register(type, resolver)` で、該当するマスと入力文脈から効果記述子の配列を返す処理を追加できます。各汚染の `params` に将来の遅延量・反復数などを保持でき、ハンドラーには元の音高・音種・voiceなどの入力文脈も渡します。現段階で登録する実効果はpoisonのdamageだけです。mute / delay / forceQuantize / echo / shieldBreak は種別と拡張点のみ用意し、音や判定への効果は未実装です。描画は `grid-hazards.css` とゲームのCanvasで行います。


### 3パートのリズムシナジー
独立した `ensemble.js` が補正前のDrums/Bass/Leadを解析します。GROOVE LOCK（KickとBassの近接）、RESPONSE（アクセント後のLead）、INTERLOCK（空白の補完）、UNISON（限られた重要拍の共有）、CALL & RESPONSE（遅れて返す非等間隔モチーフ）の5種類です。音高はモチーフ照合に使いません。

最も強い2種類だけを適用し、2つ目は60%へ逓減します。音数ではなくユニークな配置と関係の割合を評価し、過密なトラックは減点。攻撃倍率ボーナスはブレイク分を含め最大20%、追加の盾は最大6です。Leadの支援倍率、命中、盾効率、属性効果、次の反撃への耐性にも種類別の補正を加えます。反撃への耐性はその演奏直後の攻撃だけに適用し、次のDrumsでシナジー状態を消去します。単独パートの基本効果は変えません。

結果の「シナジー」タブで最大2件の理由と実際のボーナスを表示します。3パートの小型シーケンサーの点線枠は成立箇所です。追加検証：`node --test ensemble.test.cjs`。

HP／攻撃力：苔岩260／88、翼獣240／96、自律機300／104、喰らい花280／96、残響270／100、晶殻340／116。BPM・弱点・毒の性能・プレイヤー側の計算は維持しています。


### ダメージの計算詳細
戦闘結果のダメージ直下にある「計算詳細」から開きます。Drumsの基礎威力、重さ・溜め・交互入力・ノリ、POWER／Lead／シナジーの段階別倍率、敵相性とグルーヴ相性、多段の配分、命中効率、リズム精度による固定倍率を確認できます。各打撃は演奏評価値だけで決まり、命中抽選や威力のランダム変動はありません。表のダメージ合計は結果と一致します。表示数値は丸めています。

今回の変更では攻撃バランスを一律に弱体化せず、倍率が重なって大きくなる経路を追えるようにしています。計算詳細はモーダル内だけでスクロールし、閉じると元の戦闘画面へ戻ります。


### 決定論的な戦闘ダメージ
Rhythm.resolveは乱数を使いません。各打撃は `power / hits^0.85 × affinity × 命中効率 × 演奏再現性` を四捨五入します。命中効率は敵との関係を反映したaccuracyを0〜1に制限した値です。効率0は0、それ以外は最低1ダメージ。無入力は0HIT・0ダメージです。現在は1回の攻撃内の各HITも同じ固定ダメージになります。
同じ演奏・同じ敵・同じ支援／シナジー／ゾーン等の状態なら完全に同じ結果になります。意図した後ノリ・ドランク等の評価方法は維持し、単純な不規則さそのものにペナルティは与えません。


### 相性ダメージのメリハリ
属性・攻撃形態・敵とのグルーヴ相性を合成した倍率を1.65乗し、最終相性を0.4〜3倍に制限します。中立の1倍は維持。有効な相性1.5倍は約1.95倍へ、苦手な相性0.8倍は約0.69倍へ変化します。支援やシナジーの基本倍率、敵パラメータ、命中効率の算出は維持し、敵に合わせた攻撃の価値を強めています。計算詳細の「相性メリハリ補正」で変化分を確認できます。


### 演奏自体の規則性・巧さ
相性とは別に、Drumsの入力間隔の規則性と、8／16ステップ単位のフレーズ・ズレ方の反復を生時刻から評価します。規則的な刻み、または一貫した非等間隔モチーフは最大1.6倍、十分な入力数があり間隔もズレ方もばらばらな演奏は最低0.4倍になります。入力数が少ない場合は倍率を中立へ近づけ、3回以下の発音の重撃は減点しません。通常の32分・64分よりさらに細かい極端な連打で精度を稼ぐことも抑えています。

一定の後ノリ・スウィング・繰り返すドランクは単純な不規則として減点せず、パターンとズレの再現性から評価します。ライブ入力のraw timestamp／inputTimesを使い、再生補正による同一マスへの統合でも元の精度を保持します。計算詳細の「演奏再現性」で固定倍率を確認でき、大きく減点された場合は短い原因説明も表示します。


### 開発用：クオンタイズ後の評価比較
`index.html?debug=1`（または `index.html#debug`）で開くと、ヘッダーにDEVボタンが出ます。演奏を記録した後にDEVを開き、録音時の補正または任意の補正プリセットを選んで比較します。通常の起動ではボタンと記録フックは無効です。

通常評価は本番と同じ「再生用の並び＋raw基準の精度・グルーヴ・シナジー・ゾーン評価」です。補正後評価は再生用コピーの発音時刻を元入力として扱い、統合されたノートも1ノートとして、精度・グルーヴ・シナジー・ゾーン・支援・新規シールド・ダメージを再計算します。元の録音・HP・実際の戦闘結果・弱点発見・履歴は変更しません。毒の入力時ダメージも再発動しません。比較は録音終了時点の敵・BPM・ゾーンのスナップショットを使用し、持ち越し盾を除く新規生成量を表示します。

`evaluation-debug.js` は副作用のない比較処理、`evaluation-debug-ui.js` は開発専用UIです。検証：`node --test evaluation-debug.test.cjs`。

規則性・反復の評価が0.65を超えた範囲に追加ボーナスを設け、評価が高いほど加速的に報酬が増えるよう調整しました。最大精度ボーナスは従来の1.2倍から1.6倍へ引き上げ、低評価域の減点と少数の重撃の扱いは維持しています。通常プレイでは引き続きraw時刻、開発比較の補正後評価ではクオンタイズ後の時刻を使います。


### 実音声の戦闘波形
`battle-waveform.js` は、既存のマスターコンプレッサーと出力の間に1個のAnalyserNodeを挿入します。`getFloatTimeDomainData()`で実音声を読み、敵の背後の専用Canvasへ横方向の波形を描きます。元の音声データ、入力・判定・ダメージ計算、コンプレッサー設定は変更しません。音がない時は人工的な波形を生成しません。

Drumsの瞬発的な強調、Bassの持続する太い線、Leadの細かな波形を基調に、シールドの外向きパルス、POWER／BOOST／大ダメージ／敵攻撃／毒／シナジーの短い演出を加えます。属性色は攻撃時だけ表示。グルーヴの前後・スウィング・再現する揺れ・不安定さは描画の位置や薄い残像として重ね、実波形サンプルには書き戻しません。

波形の解析バッファは使い回し、描画は最大320点、DPRは最大1.5。小さい表示領域では30fpsへ抑え、ResizeObserverでサイズへ追従します。非表示タブでは描画を停止し、OSの動きを減らす設定では追加の残像・パルスを抑制します。`BattleWaveform.registerRenderer(name, draw)` と `setRenderer(name)` で将来の円形波形・スペクトラム描画へ差し替えられ、描画フレームにはAnalyserNodeも渡します。`dispose()`は解析・描画を解放し、音声は元の直接出力へ戻します。

検証：`node --test battle-waveform.test.cjs`。

## ゲーム内シンセ

演奏エリアの「シンセ」からBASS / LEADを個別に編集できます。Sine / Triangle / Saw / Square、Cutoff（80〜16000 Hz）、Resonance、Attack / Decay / Sustain / Releaseに対応。「試聴」で鳴らしながら調整でき、音色はブラウザに自動保存します。ドラムは従来の埋め込みサンプルです。設定ダイアログだけが必要に応じてスクロールし、演奏画面ではエフェクトパッドと演奏開始ボタンを表示します。

エフェクトパッドはマウス移動、スマートフォンのタッチ、矢印キーで操作します。上下が音量、左右がフィルター。LOW PASSは設定したCutoffから暗くし、HIGH PASSは低域を削りながら明るくします。パッドからマウス／指が離れると、音量100%・フィルター操作0%へ戻ります。シンセのCutoff設定自体は変えません。ベース／リードでは、パッド内の小さな4本のゲージにも音色属性を表示します。

音色属性は波形の倍音、実効Cutoff、Resonance、ADSRの組み合わせで計算し、炎・水・風・土の配分を合計100%に正規化します。炎は攻撃が強い代わりに盾が弱く、水は湿潤で敵を弱める代わりに攻撃が弱く、風は命中効率が上がる代わりに盾が弱く、土は盾が強い代わりに攻撃と命中効率が下がります。属性の抽選や固定の最強プリセットはありません。

戦闘には、録音した発音区間をエンベロープ音量とパッド音量で重みづけした平均属性を使います。同じパートの音が重なる場合は後発ノートで前の発音区間を打ち切り、音符の積み重ねで属性ボーナスを増やしません。無音は補正なし。攻撃と命中はBass / Leadを各1/2で合成し、既存のリズム・グルーヴ・アンサンブル計算の後に一度適用します。盾はBassの元の盾量にBass音色を全量、Lead音色を半量で反映。水の湿潤は今回の敵反撃にだけ作用し、両パート合計で最大12%、既存の軽減と合わせて最大55%です。既存のドラム属性・敵相性は上書きしません。旧パッドの単独の攻撃／盾加算は音色補正に統合しました。

各パートの録音に、開始音色と音色・パッドの変化を保存します。カウントインの先取り入力にも対応します。バッキング、攻撃再生、リプレイ、履歴再生は保存したパートごとの音色を使用し、現在の設定を変更しても録音の音は変わりません。波形切り替え・Cutoff・音量はWeb Audioのオーディオ時刻で予約し、長いReleaseまで再生します。JSON書き出し／読み込みも音色とオートメーションを保持します。MIDIは従来どおり音符とテンポのデータで、この独自シンセの音色は含みません。古いJSONも読み込めますが、音色情報がない旧録音には現在のシンセ音色を使います。

実装は `synth.js`（音色・属性・保存形式）、`synth-audio.js`（発音・ADSR・オートメーション・Kickダッキング）、`synth-ui.js` / `synth.css`（編集画面とゲージ）に分離しています。ゲーム側は既存の共通コンプレッサーと波形アナライザーを利用し、シンセとドラムのフィルター経路を分けてCutoffの二重適用を避けています。戦闘結果にはパートごとの属性と補正、ダメージ計算詳細には合成した音色倍率を表示します。

検証：`node --test *.test.cjs`。ブラウザ検証は開発用のPlaywrightがある環境で `node scripts/synth-browser-check.cjs` を実行します（必要なら `RIDUMU_PLAYWRIGHT_PATH` と `RIDUMU_CHROME` で場所を指定）。ゲーム本体は引き続き外部ライブラリ・サーバー・ネット接続不要です。


BASS / LEADはそれぞれ独立したモノフォニック音源です。新しい音を押すと同じパートの前の音とReleaseの余韻を打ち切り、後から押した音を優先します。新しい音を離しても、押したままの古い音へは戻りません。切り替え時は短いフェードでクリックを抑えます。BassとLeadは同時に鳴らせます。録音は前の音の長さを切り替え位置で確定し、既存の重なった録音も再生時に同じ規則で発音します。


リードの初期音色はシンセ導入前の音を再現しています。Triangleに1オクターブ上のSineを18%重ね、Cutoffを3600→1800 Hzへ0.12秒で減衰。音量は指数カーブでAttack 0.008秒、Decay 0.072秒、Sustain 65%、Release 0.12秒です。「以前のリードに戻す」で復元できます。シンセには倍音量、Filter Decay、Filter Sustain、Linear / Exponentialの音量カーブを追加し、変更も録音・JSON・属性計算へ反映します。旧版の変更していない初期設定は自動移行し、カスタム設定と既存の録音は旧パラメータを補完して読み込みます。
### 演奏中心のUI
戦闘と演奏を常時表示し、現在のパート・次の操作・拍・2小節の進行を大きく示します。「設定」から再生補正、音数・音高、シンセ、記録・発見へアクセスできます。結果はダメージ／シールド／属性を先に表示し、「解析・内訳を見る」で従来のリズム、アンサンブル、計算内訳と再生を利用できます。

「効果」は戦闘エリアに重ねて開くため、演奏パッドと開始ボタンの位置や大きさは変わりません。開閉状態をブラウザに保存し、閉じるとパッド効果を初期値に戻します。設定・解析画面は内部でスクロールし、通常の演奏画面は画面内に収まります。

表示の組み立ては `ui.css`、既存エンジンを監視する案内・ダイアログ操作は `ui.js` に分離しています。音声・判定・戦闘計算は従来の処理を使用します。検証：`node --test`、Playwright環境で `node scripts/ui-browser-check.cjs` と `node scripts/synth-browser-check.cjs`。
### 連続入力オプション
「設定」→「タイミング」→「連続入力」をONにすると、最初の開始操作だけでHAT → DRUMS → BASS → LEADへ2小節ずつ連続入力できます。カウントイン／リムショットとパート間の開始操作を省略し、パートの開始時刻を同じ音声クロック上で引き継ぎます。通常モードは従来どおりです。設定はブラウザに保存します。

リード後は従来の戦闘処理を行い、生存中は次のHATから自動継続します。停止ボタンまたはEscで入力を中断でき、入力中のパートは録り直しになります。完了済みのパートは保持します。戦闘中に停止した場合は戦闘完了後に止まり、撃破・敗北時も自動入力を終了します。
