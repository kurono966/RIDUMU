# RIDUMU

index.html をブラウザで開くと遊べます。インストール、サーバー、外部API、ネット接続は不要です。

## 演奏の流れ

1. 「演奏開始」またはSpace。敵のBPMで4拍カウントイン。
2. **HI-HAT：Space / H / Hatパッド**で2小節演奏。リムショットの拍カウントを聴きながら、自分でHatの基準を作ります。
3. 4拍の切り替えカウント後、**A＝Kick / L＝Snare / タッチパッド**で2小節重ねます。録ったHatを生タイミングで再生し、固定の自動Hatは鳴らしません。
4. Hatと入力パートを自動再生。音のタイミングでダメージが入り、終了後に敵が反撃します。
5. ベース・リードのターンは録ったHatをそのまま使い、2入力の演奏へ進みます。Hatの再入力は不要です。

1セットは **Hat → Kick/Snare → ベース → リード**。ドラムに戻ったときだけ全パートをリセットし、新しいHatから始めます。Hatを無入力で終えた場合も、そのセットでは再入力を求めません。

各フェーズのカウントインは最後の1拍から先取り入力できます。発音と再生には生時刻を使い、解析用の16分グリッドに入力を強制しません。長押しによるOSキーリピートは除外します。

## 敵のテンポとグルーヴ

| 敵 | BPM | 2小節の長さ |
| --- | --- | --- |
| 苔岩の番人 | 82 | 約5.85秒 |
| 宙を舞う翼獣 | 150 | 3.2秒 |
| 忘却の自律機 | 120 | 4秒 |

カウントイン・拍ランプ・録音時間・解析グリッド・再生が敵のBPMに追従します。速い敵ほど一律に強くする設計ではありません。敵ごとに異なるノリが有効になり、有効な相性は攻撃して発見します。

Hatの平均間隔・平均ズレ・前後の置き方・裏拍・均一性・スウィング・繰り返すズレ・小節単位の再現性・ランダムな不安定さを記録します。Kick/Snareは近いHatとの生時刻差も解析し、pocket / laidBack / pushed / swing / drunk / tight / unstable を連続値で保持します。Hatが少ないときはグルーヴを捏造せず、従来の音の特徴で攻撃します。

一定のSnareの遅れや、繰り返す非等間隔パターンは「不安定」と区別します。音種ごとの平均差を取り除いてから複雑な揺れを評価するため、単純なKick前／Snare後を自動でドランクにはしません。2小節内の反復から推定するMVPであり、プレイヤーの意図そのものを確定するものではありません。

## 継続して使える要素

- ドラム → ベース → シンセリードの3ターン周期。Hatはセットの最初だけ録音し、同じHatと前の入力パートを伴奏として重ねられます。ドラムに戻ると全パートをリセット。次の敵も新しいHat・ドラムから開始します。
- 土・風・火・雷の4属性と既存リズム解析。ノリが威力・命中・ばらつき・属性・敵との相性にも影響します。Hatや過去の伴奏は直接の追加打撃に換算しません。
- 原タイミングの手動リプレイ。録音時のBPM・長さ・全パートを保持します。
- 命中時の弱点ラベル、最大3要因の説明、合計と一致するダメージ内訳、Hatを含む3段シーケンサーと原因ハイライト。
- 「SnareがHatより平均35ms後ろ → レイドバック」など、音楽的な言葉で結果を説明します。
- 発見した弱点・グルーヴ相性は敵の上部と「発見メモ」で確認できます。localStorage に保存し、保存できない環境ではプレイ中だけ保持します。
- 狭い画面は結果説明・リズム表示を切り替え、小さい横画面では内訳とヒントも分けます。

## ファイルと検証

- groove.js：Hat解析、Hatと2入力の相対関係、ノリのスコアと戦闘への反映。
- rhythm.js：既存特徴量・4属性・敵相性・ダメージと内訳・再生時刻。
- game.js：2フェーズ進行、Web Audio合成音、記録・再生・戦闘・可視化。
- feedback.js / feedback-ui.js：説明・原因選択・弱点発見・保存。
- style.css / feedback.css / groove.css：画面構成。
